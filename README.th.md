## ✨ ทำอะไรได้บ้าง

คุยกับมันได้เหมือนคุยกับคน — ภาษาไทยหรืออังกฤษ มันตอบด้วยเสียงที่เป็นธรรมชาติ แสดงอารมณ์ด้วยดวงตาบนจอ
จำเรื่องของคุณข้ามวันได้ และดึงข้อมูลสด (อากาศ, ราคาน้ำมัน, หุ้น, ข่าว ฯลฯ) มาแสดงเป็นกราฟิกบนจอระหว่างที่อธิบาย
ทุกอย่างทำงานบนบอร์ดเอง: **ไม่ต้องมี server, ไม่ต้องมี Raspberry Pi, ไม่ต้องมี vector database** — ใช้แค่ Wi-Fi กับ Gemini API key

| 🧑‍💼 **บุคลิก** | โปรไฟล์สำเร็จรูป 8 แบบ (ไข่มุก, ภูมิ, ลีน่า, ธันวา, มะปราง, โอม, น้ำ, ครูเก่ง), เสียง 30 แบบ, นิสัย 7 แบบ, ลงท้าย ค่ะ/ครับ — เปลี่ยนผ่านเมนูทัชหรือสั่งด้วยเสียง |
| 👀 **ใบหน้ามีชีวิต & เมนูสมาร์ทวอช** | ดวงตาสไตล์ Cozmo 14 อารมณ์, ซับไตเติลภาษาไทย, ไอคอนคมชัดแบบ anti-aliased (ปุ่มไมค์มุมซ้ายล่าง), status bar สูงเท่ากัน (Wi-Fi แบบพัด + เวลา Oswald), ตรวจจับไฟ `USB ⚡` / `% แบต` อัตโนมัติ (T170: แยก USB / แบตจากการกระโดดของแรงดันตอนเสียบ/ถอด + สัญญาณ USB ของ PC, % เปลี่ยน ≤ 1 %/นาที - บน USB ขึ้นอย่างเดียว บนแบตลงอย่างเดียว - และ `% ⚡` ตอนชาร์จ; console `bat`), ปุ่มลัดมุมขวาล่างเปิดได้ทั้ง **เครื่องเล่น วิทยุ/MP3 (`♫`)** และ **หน้าปัดรถ**, พร้อม **เมนูตั้งค่าสไตล์สมาร์ทวอช** (การ์ดไอคอนสีสันสดใส 8 หมวด 2 หน้า ปัดซ้าย/ขวาได้) — พักนานจะเปลี่ยนเป็น**หน้าจอพักนาฬิกาหรี่แสง 7 ธีม** (*ดิจิทัล + สภาพอากาศ*, *สมาร์ทวอช วงแหวน*, *ฟลิปการ์ด ไซเบอร์*, *คลาสสิก มินิมอล*, *อนาล็อก เข็มนาฬิกา*, *ตัวเลขใหญ่ ตั้งโต๊ะ*, *ดวงอาทิตย์ & ดวงจันทร์*) เลือก**สีนีออนได้ 9 สี** (ฟ้า เขียว ชมพู ส้ม เหลือง ม่วง แดง ขาวนวล หรือตามสีดวงตา) นาฬิกาใหญ่เต็มจอ แสดงเวลา วันที่ไทย และสภาพอากาศสด + PM2.5 ของจังหวัดที่เลือก และตื่นพร้อมจอสว่างทันทีที่ได้ยินคำปลุกหรือแตะจอ |
| 📊 **การ์ดข้อมูลสด** | อากาศ + PM2.5, ราคาน้ำมันไทย, หุ้น/ทอง/คริปโต/ค่าเงิน, วิเคราะห์เทคนิค, สแกนหุ้น, ปฏิทินเศรษฐกิจ, ข่าว, Wikipedia — วาดเป็นกราฟิกขณะ AI พูด |
| 📻 **วิทยุออนไลน์** | หน้าจอแบบแอปวิทยุ พร้อม 16 สถานีไทยที่ทดสอบแล้ว (เพิ่มได้ถึง 40 — `python tools/radio_check.py` ตรวจรายชื่อสถานีแบบเดียวกับที่บอร์ดเล่น; ถอดรหัส AAC ที่เฟรมเสียไม่ค้างจนรีบูตแล้ว): เลื่อนแล้วแตะเลือกสถานี ปุ่มเพิ่ม/ลดเสียง ปุ่ม ⏸ หยุดชั่วคราว ปุ่ม ⏻ ปิดวิทยุ (สีแดง) และแตะกลางจอเพื่อสั่งงาน AI ได้เหมือนเดิม พูด "เปิดวิทยุลูกทุ่ง" หรือ "สถานีที่ 4" แล้ว AI จะเลือกจากรายการให้ แก้รายการ (เพิ่ม แก้ ลบ เรียงลำดับ ทดสอบ URL) ได้ใน ESP32-AI Studio ถอดรหัส MP3/AAC ด้วย Helix และวิทยุจะเบาลงเหลือ 12% ระหว่างคุย ปุ่มปรับเสียงและคำสั่ง "เบาเสียงหน่อย" ปรับเฉพาะวิทยุ — เสียง AI ล็อกไว้ที่ระดับของตัวเอง (ค่าเริ่มต้น 80, `set aivolume`) สั่งเปิดวิทยุแล้ว AI บอกชื่อสถานีแล้วพักทันที (ไม่ฟังหรือตอบเสียงดีเจ) และสั่ง "เปิดวิทยุ" เฉยๆ จะเล่นสถานีล่าสุด ถามข้อมูล (อากาศ ข่าว ...) ระหว่างเปิดวิทยุ เซสชันจะรอจน AI ตอบเสร็จ (T119) **เพลง MP3 จาก SD card (T122):** ปุ่มสลับ [วิทยุ | MP3] บนหน้าวิทยุ เล่นเพลงในโฟลเดอร์ `music` ของ SD card (และโฟลเดอร์ย่อย 1 ชั้น) แสดงชื่อเพลงและศิลปินจาก ID3 tag (รองรับ tag ภาษาไทย) หรือชื่อไฟล์ จบเพลงเล่นเพลงถัดไป หยุดแล้วเล่นต่อจากจุดเดิม สั่งด้วยเสียง "เปิดเพลง ...", "เปลี่ยนเพลง", "เพลงก่อนหน้า", "สุ่มเพลง" หรือ console `music` ถ้าการ์ดหยุดตอบ บอร์ด mount ใหม่เองโดยไม่ต้องรีบูต (T125) **ใส่เพลงจาก PC (T123):** ESP32-AI Studio → แท็บ 🎵 เพลง (SD) ส่งไฟล์ MP3 ลงการ์ดผ่านสาย USB (ตรวจ sha256, ~140 KB/s ≈ 1 นาทีต่อเพลง 8 MB) ดูรายการ เล่น และลบได้ — ใช้ตัวถอดรหัสเดียวกับวิทยุ ไม่กิน RAM เพิ่ม [wiki/12](wiki/12-Internet-Radio.md) |
| 🏁 **หน้าปัดรถ** (ใหม่, **เฉพาะ ES3C28P** — ไม่มีในเฟิร์มแวร์ P4 และบอร์ดจิ๋ว) | หน้าปัดรถยนต์และมอเตอร์ไซค์ 3 รูปแบบ — **รถแข่ง** (บาร์รอบ), **วงกลมดิจิทัล สปอร์ต** (วงแหวนไฟ) และ **เข็มวงกลม คลาสสิก** (วัดรอบ + ความเร็ว) — มี shift light, ความเร็ว, เกียร์, ช่องอุณหภูมิเครื่อง / แบต / อากาศเข้า เปลี่ยนเป็นเหลือง/แดงเมื่อเกินเกณฑ์ เปิดด้วยปุ่มรูปหน้าปัดมุมขวาล่างของหน้าหลัก หรือพูด "เปิดหน้าปัด" (ยังไม่ได้เลือกแหล่งข้อมูล = เปิดตัวจำลองให้) แตะแถบหัวเพื่อสลับแบบ ข้อมูลจาก **Honda K-Line** (Wave 110i / 125i, Click, PCX ... ผ่านบอร์ดแปลงแบบ L9637D), OBD-II ผ่าน ELM327 ต่อสาย, ข้อความจากบอร์ดอื่น หรือตัวจำลองในตัว (นิ้วเป็นคันเร่ง) — ELM327 แบบ Bluetooth LE (หรือ dual-mode) ใช้เฟิร์มแวร์แยก `pio run -e esp32s3-ble -t upload` (ไม่อยู่ใน release ตั้งแต่ T192 — RAM ~23 KB ของบลูทูธให้สตรีมราคาสดแทน) — ตั้งแต่ T113 ใช้ OBD ผ่านบลูทูธพร้อมผู้ช่วยเสียงได้ (ย้าย buffer/ออบเจกต์ไป PSRAM, pool ของ NimBLE อยู่ใน PSRAM, ฟังคำปลุกคำเดียวขณะใช้บลูทูธ; บลูทูธเปิดเฉพาะตอนเปิดหน้าปัด ปิดหน้าปัดแล้วได้ RAM คืน) **ล็อกภาษาของ AI (T116):** ตั้งค่า "ภาษาที่ AI พูด" ไทย (ล็อก, ค่าเริ่มต้น) / English / ตามภาษาที่ผู้ใช้พูด (`set language th` / `en` / `auto`, Studio) **log OBD + เล่นย้อนหลัง (T115; ตรวจ log จากรถจริงครั้งแรกใน T117: แก้ VIN ที่รถตอบ "รอสักครู่"):** ทุกคำสั่ง/คำตอบของ adapter สถานะ เหตุการณ์ ค่าทุกวินาที รหัสปัญหา และสุขภาพรถ ลง SD card (`agent/obdlog`, sync ทุก 2 วิ) ดึงลง PC ด้วย `python tools/obd_log.py` (`pull`, `summary`, `csv`, `replay`) และแหล่งหน้าปัด "เล่นย้อนหลังจาก log" เล่นการขับที่บันทึกไว้ผ่านตัวคุยกับ ELM327 ตัวเดิม — อัปเดต OTA จะได้เฟิร์มแวร์ปกติที่ไม่มีบลูทูธ AI อ่านค่าสดได้ ("เครื่องร้อนไหม") และพูดเตือนเองเมื่อเครื่องร้อนจัดหรือไดชาร์จไม่ชาร์จ **OBD-II อัจฉริยะ (T112):** หาโปรโตคอลของรถเอง (จำไว้ และลองทีละตัวเมื่อ adapter หาเองไม่เจอ) และหา baud ของ adapter เอง อ่าน**ทุก PID ที่รถมี** โดยอ่านตัวที่จำเป็นก่อน (เร็วตอนเปิดหน้าปัด ช้าลงตอนปิด) **รหัสปัญหาพร้อมความหมาย** (stored / pending / permanent) freeze frame, VIN, readiness และล้างรหัส **วิเคราะห์สุขภาพรถ**จากค่าสด (ความร้อนขึ้นเร็ว ไดชาร์จไม่ชาร์จ แบตอ่อนตอนจอด/ตอนสตาร์ท ส่วนผสมบาง/หนาหรือมีรอยรั่วอากาศ เดินเบาไม่นิ่ง น้ำมันใกล้หมด) และ**ทริปพร้อม กม./ลิตร** (จาก PID อัตราใช้น้ำมัน, MAF หรือ MAP) ใช้ความเร็วจาก GPS มือถือเมื่อกล่องมอเตอร์ไซค์ไม่มี หน้าปัดแบบที่ 4 **"ข้อมูลรถ + วิเคราะห์"** (9 ค่า, รหัสปัญหา, สิ่งผิดปกติที่ร้ายแรงสุด) และไอคอนเครื่องยนต์สีอำพันเมื่อไฟเช็คเครื่องติด ถาม "รถเป็นยังไงบ้าง" "สแกนรถให้หน่อย" "P0420 คืออะไร" (ไม่ต้องมีรถ) หรือ "ล้างรหัสปัญหา" — ตัวจำลองในตัวมีรหัสปัญหาด้วย ลองได้ทั้งหมดโดยไม่มีรถ — ยังไม่ได้ทดสอบกับรถจริง [wiki/16](wiki/16-Vehicle-Dash.md) |

### ทางเลือก A — ใช้เฟิร์มแวร์สำเร็จรูป (ไม่ต้องลงโปรแกรมพัฒนา)

1. ดาวน์โหลด `PersonalAIBot-ESP32-v…-factory.bin` จากหน้า **[Releases](https://github.com/skyliner2008/PersonalAIBot-ESP32/releases)**
   บอร์ดอื่นมีไฟล์ของตัวเอง (ตั้งแต่ release ถัดไป): `-factory-p4.bin` (ESP32-P4), `-factory-xh-s3e-ai.bin` (XH-S3E-AI),
   `-factory-xmini-c3.bin` (Xmini-C3) — อัปเดตผ่าน Wi-Fi ก็หยิบเฉพาะ `-app-….bin` ของบอร์ดตัวเอง
2. เปิด **[espressif.github.io/esptool-js](https://espressif.github.io/esptool-js/)** ด้วย Chrome หรือ Edge เสียบบอร์ดด้วยสาย USB-C แล้วกด **Connect**
   (ถ้าหาบอร์ดไม่เจอ: กด **BOOT** ค้าง → แตะ **RESET** → ปล่อย BOOT แล้วกด Connect ใหม่)
3. ช่อง Flash Address ใส่ **`0x0`** → เลือกไฟล์ `.bin` → **Program** เสร็จแล้วกด **RESET** ที่บอร์ด

ใช้ command line ก็ได้: `esptool.py --chip esp32s3 write_flash 0x0 PersonalAIBot-ESP32-v4.9.4-factory.bin`

**📱 แอปเล็กสำหรับแฟลช (T195):** **`ESP32-AI-Flasher.apk`** จาก release (~0.8 MB ขอสิทธิ์แค่อินเทอร์เน็ต) ทำแค่: ตรวจว่าเสียบบอร์ดรุ่นไหน (4 รุ่น) → โหลดเฟิร์มแวร์ล่าสุดจาก GitHub แฟลชให้ · ตั้งค่า · ดู log (`python tools/build_flasher_apk.py`) — ถ้ามีแอป Flasher 1.0 เดิม ให้ถอนก่อนครั้งเดียว · บอร์ดที่รันเฟิร์มแวร์อื่น (เช่น XiaoZhi) ซึ่งไม่อ่านคำสั่ง จะขึ้น "บอร์ดไม่รับคำสั่ง" และค้างการเชื่อมต่อไว้ ไม่วนต่อ/หลุดอีก (Flasher 2.1.2, T207) — แฟลชกลับที่แท็บแฟลช ถ้าไม่ผ่าน: กด BOOT ค้าง แตะ RESET แล้วปล่อย BOOT ก่อน

**📱 แฟลชจากมือถือ Android (ไม่ต้องมีคอม):** ติดตั้งแอปมือถือ **Personal AI Bot** (`PersonalAIBot-Mobile.apk` — ไม่อยู่ใน release ตั้งแต่ v4.9.6 (T196, ~225 MB) ให้ build เอง:
`python tools/build_mobile_apk.py`) แตะไอคอนชิปที่แถบบนเพื่อเปิดหน้า **บอร์ด ESP32** เสียบสาย USB-C จากมือถือเข้าบอร์ด (มือถือต้องรองรับ USB OTG) แล้วกด **แฟลชลงบอร์ด**
แอปดาวน์โหลด release ล่าสุดเองและตรวจ sha256 (และลายเซ็นของ release) · **อัปเดต** เขียนไฟล์ `-app.bin` โดยค่าที่ตั้งไว้และความจำอยู่ครบ ·
**ติดตั้งใหม่ทั้งหมด** เขียนไฟล์ factory · เลือกไฟล์ `.bin` ในเครื่องก็ได้ · ใช้ได้เฉพาะ Android 8 ขึ้นไป (iOS ไม่ให้แอปใช้ USB serial)
แอปเดียวกันนี้ใช้เป็น **ESP32-AI Studio ฉบับพกพา** ผ่านสายเส้นเดิมได้ด้วย: ดูสถานะ + ปุ่มด่วน (ไมค์ / พัก / ปลุก / ต่อ AI ใหม่ / บทสนทนาใหม่ / รีบูต),
พิมพ์แชทกับผู้ช่วย, log สด (กรอง, แชร์, พิมพ์คำสั่ง console) และตั้งค่า (สแกน Wi-Fi, API key + ทดสอบ, โปรไฟล์, เสียง, โมเดล, ความดัง, ความสว่าง ...) — ดู [wiki 17](wiki/17-Mobile-Flasher.md)
แอป**อัปเดตตัวเองได้**จากหน้า release: ตั้งค่า → **อัปเดตแอป** (ตรวจเองวันละครั้ง ตรวจ sha256 แล้ว Android ถามก่อนติดตั้ง ข้อมูลในแอปอยู่ครบ) — ใช้ได้กับ release ที่มี `PersonalAIBot-Mobile.json` (ตั้งแต่ v4.4.2)

> ไฟล์ factory เริ่มที่ `0x0` จึง**ล้างค่าตั้งค่าเดิมในบอร์ด**ไปด้วย (ติดตั้งใหม่สะอาด)
>
> **บอร์ดเป็น v3.5.0 ขึ้นไปแล้ว?** อัปเดตผ่าน Wi-Fi ได้เลย: เมนูตั้งค่า → **อัปเดตเฟิร์มแวร์** บอร์ดดาวน์โหลดไฟล์ `-app.bin` ของ release ล่าสุด ตรวจ (sha256, header, เวอร์ชัน และลายเซ็นของ release เมื่อตั้งกุญแจแล้ว) แล้วติดตั้ง โดย**ค่าที่ตั้งไว้และความจำอยู่ครบ** ถ้าเวอร์ชันใหม่เปิดไม่ผ่านจะกลับเป็นเวอร์ชันเดิมเอง · เช็คอัปเดตได้แม้เปิดวิทยุหรือ AI กำลังพูด (T121: handshake TLS กับ GitHub รันที่ priority สูงขึ้น — เดิมช้าจน GitHub ตัด ขึ้น "ติดต่อ GitHub ไม่ได้ (HTTP -1)") — ดู [wiki 13](wiki/13-OTA-Update.md)

### บูตครั้งแรก — ใส่ Wi-Fi และ API key ของคุณเอง

1. **ปรับแต่งทัช** — แตะเป้า 3 จุด
2. แตะ ⚙ (หรือกด **BOOT** ค้าง 1.5 วิ) → **Wi-Fi** → สแกนแล้วเลือกเครือข่าย → พิมพ์รหัสด้วยคีย์บอร์ดไทย/อังกฤษบนจอ
3. **API key** → พิมพ์ key → **ทดสอบ API key** จะบอกว่า key ใช้โมเดลไหนได้บ้าง
4. เมื่อจอขึ้น **"พร้อมคุย"** — พูดได้เลย

**หรือตั้งค่าจากคอมพิวเตอร์ผ่านการ์ด SD:** คัดลอก [`tools/sd_card/ai-setup.txt`](tools/sd_card/ai-setup.txt) ไปไว้ที่หน้าแรกของการ์ด
micro SD (FAT32) กรอก `WIFI_SSID`, `WIFI_PASSWORD`, `GEMINI_API_KEY` แล้วเสียบการ์ดเข้าบอร์ดและเปิดเครื่อง
บอร์ดจะอ่านไฟล์ เก็บค่าแบบเข้ารหัสใน `agent/secrets.json` บนการ์ด แล้วลบไฟล์ข้อความธรรมดาทิ้ง
(ปุ่ม **💾 ไฟล์สำหรับการ์ด SD...** ใน Studio สร้างไฟล์นี้ให้ได้)

ไม่อยากพิมพ์บนจอเล็ก? ใช้แอป PC (หัวข้อถัดไป) ตั้งค่าได้ทุกอย่าง

### ESP32-AI Flasher สำหรับ Windows (ง่ายที่สุด)

**`ESP32-AI-Flasher.exe`** จาก [release ล่าสุด](https://github.com/skyliner2008/PersonalAIBot-ESP32/releases/latest) — ไฟล์เดียว ~100 KB สำหรับ Windows 10/11 ไม่ต้องติดตั้ง (T199) เสียบบอร์ดด้วยสาย USB แล้วโปรแกรมต่อให้เอง มี 5 แท็บเหมือนแอปมือถือ: สถานะบอร์ด + แชท, log, ตั้งค่า (Wi-Fi, API key, ผู้ช่วย, โมเดล, เครื่อง), **เครื่องมือ** (หน้าจอบอร์ด + แตะสั่ง, วิทยุ / MP3, ไฟล์ในการ์ด SD) และ **แฟลช** — เฟิร์มแวร์ล่าสุดลงบอร์ดได้ทั้ง 4 รุ่น บอร์ดใหม่ก็ได้ ("ติดตั้งใหม่ทั้งหมด" — แยก ESP32-S3 สองรุ่นด้วยการสแกนขา I2C) · ถ้า SmartScreen ถาม: *More info → Run anyway*

### ESP32-AI Studio (แอปบน PC, ไม่บังคับ)

**ไม่ต้องมี Python (T194):** ดาวน์โหลด **`ESP32-AI-Studio.exe`** จาก [release ล่าสุด](https://github.com/skyliner2008/PersonalAIBot-ESP32/releases/latest) แล้วดับเบิลคลิกได้เลย (Windows 10/11 ไฟล์เดียว ไม่ต้องติดตั้ง — ถ้า SmartScreen ถาม: *More info → Run anyway*) ใช้ได้ทุกแท็บ ยกเว้น Build / Upload / host tests ที่ต้องมีซอร์สโค้ด · **แท็บ 🔧 → แฟลชผ่านสาย USB (T197)** เขียนเฟิร์มแวร์ล่าสุดจาก GitHub ลงบอร์ดทั้ง 4 รุ่น — บอร์ดใหม่ก็ได้ ("ติดตั้งใหม่ทั้งหมด" — สแกนขา I2C แยก ES3C28P / XH-S3E-AI ให้เอง, T198) และอัปเดตผ่าน Wi-Fi ได้ด้วย ไฟล์อัดเสียงเก็บที่ `Documents\ESP32-AI Studio\recordings`

## 🛠️ Tools

AI เลือกเรียกเองตามบทสนทนา tool ข้อมูลทำงานใน task เบื้องหลังและวาดการ์ดบนจอขณะ AI พูดต่อได้ • ถามหลายอย่างในประโยคเดียว ("ราคาทอง อากาศวันนี้ และข่าว") การ์ดจะเข้าคิวและขึ้นทีละใบตอนที่เสียงพูดถึงเรื่องนั้น ข้อความของ AI ขึ้นจอตามจังหวะที่ลำโพงพูดจริง (T210) • ถามข้อมูลเดิมซ้ำภายในเวลาที่ข้อมูลยังสด (อากาศ 10 นาที, น้ำมัน 30 นาที, ข่าว 5 นาที, ราคา 1 นาที) ตอบจากที่จำไว้ทันที ไม่ต้องดึงใหม่ • ถามอากาศจังหวัดใดก็ได้ใน 77 จังหวัด ~3 วิ (มีพิกัดในตัว ไม่ต้องค้นหาตำแหน่ง และงานที่มีคนรออยู่ได้ CPU ก่อนภาพเคลื่อนไหวบนจอ)

**ล่ามแปลภาษา + จดบันทึกประชุม (T212, ES3C28P + ESP32-P4)** — "ช่วยเป็นล่ามภาษาญี่ปุ่น" บอร์ดสลับไปใช้ Gemini 3.5 Live Translate พูดคำแปลของทุกประโยคที่ได้ยิน พร้อมซับทั้งสองฝั่ง แตะจอ = สลับทิศ พูด "หยุดแปล" = กลับมาคุยกับผู้ช่วยต่อจากเดิม • "ช่วยจดประชุม" สลับไปใช้ Gemini 3.5 Transcribe Live ขึ้นซับสด เก็บข้อความใน `agent/meetings/` แล้วให้ผู้ช่วยสรุป (`meeting_notes read`) • ปัจจัยพื้นฐานหุ้นครบขึ้น (หนี้ เงินสด margin ROE ราคาเป้านักวิเคราะห์) แปลงเป็นสกุลเงินของราคา (TradingView ให้งบหุ้นไทยเป็น USD) (T211)

**จอแสดงภาษาญี่ปุ่น จีน เกาหลี และภาษาอักษรละติน/รัสเซีย (T213, ES3C28P / ES3C35P)** — ซับของโหมดล่ามและการ์ดแสดงตัวอักษรของภาษานั้นได้จริง (เดิมเป็นช่องว่าง): ญี่ปุ่น (คานะ + คันจิ 4,425 ตัว) จีนตัวย่อ (3,755 ตัวที่ใช้บ่อย) เกาหลี (ฮันกึล 2,350 ตัว) ฝรั่งเศส เยอรมัน สเปน อิตาลี โปรตุเกส เวียดนาม ตุรกี โปแลนด์ รัสเซีย และคำอ่าน pinyin / romaji — ผสมกับภาษาไทยในบรรทัดเดียวกันได้ ฟอนต์จีน/เกาหลีตัดย่อจากฟอนต์ /efont/ ของ LovyanGFX (สัญญาอนุญาตแบบ BSD — ดู `src/display/fonts/efont/COPYRIGHT.txt` ในซอร์ส), ตัวละตินจาก Noto Sans (© 2012 Google Inc., Apache License 2.0), ญี่ปุ่นใช้ IPA Gothic ที่มากับ LovyanGFX • ใช้ flash +534 KB (เหลือ 253 KB) • ESP32-P4 ยังไม่มี

**คาดการณ์ล่วงหน้าคิดเป็นเงิน USD (T225, ES3C28P + ESP32-P4)** — `market_anticipation` มีบัญชีให้ตั้ง: ยอดเงิน, spread (จุด), lot, leverage (ค่าเริ่มต้น 1000 USD, 32 จุด, 0.01 lot, 1:2000 — เปลี่ยนด้วย `config` `set: "balance=…,spread=…,lot=…,leverage=…"` หรือสั่งด้วยเสียง) · สรุปผลบอกกำไร/ขาดทุนรวมเป็นดอลลาร์ (หัก spread แล้ว) และยอดเงินคงเหลือ พร้อมเงินของแต่ละไม้ข้าง R · `analyze` บอกว่าชน SL เสียเท่าไร ชน TP ได้เท่าไร ค่า spread, margin และความเสี่ยงเป็น % ของบัญชี · การแจ้งเตือนบอกเงินต่อท้าย · ประวัติ 30 วัน (`antic_track.json` v2) เก็บระยะราคาแต่ละวัน (เติมย้อนหลังจากมุมมองที่บอร์ดเก็บไว้) → สรุปผลมี `history_usd` ผลรายวันย้อนหลัง 7 วันเป็น R และดอลลาร์ พร้อมยอดเงินคงเหลือ · คิดได้กับทอง เงิน BTC/ETH และคู่เงินที่อ้าง USD — สินทรัพย์อื่นยังบอกเป็น R (ไม่เดาขนาดสัญญา)

**แอป Android แฟลชได้เหมือนตัว Windows (T239, ESP32-AI-Flasher.apk 2.2.0)** — แท็บแฟลชมีปุ่ม "🔍 สแกนบอร์ด" แล้ว: อ่านชิป, flash, PSRAM, ขา, ชิปบนสาย I2C และ log ตอนบูต โดยไม่เขียนอะไรลงบอร์ด แล้วบอกผลพร้อมปุ่มส่ง / คัดลอก / บันทึกรายงาน (ดาวน์โหลด/ESP32-AI-Flasher) • ก่อนลบ แอปถามชิปบนบอร์ดว่าเป็นรุ่นไหนจริง: Waveshare 1.54, XH-S3E-AI และ SenseCAP Watcher ไม่ต้องเลือกรุ่นเองแล้ว และ JC3248W535 จะไม่ได้เฟิร์มแวร์ของ ES3C35P • หยุดเมื่อไฟล์ใหญ่กว่า flash จริงของบอร์ด, รู้จัก ESP32 รุ่นแรก / S2, คุยกับบอร์ดที่ใช้ชิปแปลง USB-serial ได้ (CH342 / CH343 / CH9102, CH340 / CH341, CP210x) • ทดสอบจาก PC กับ ES3C28P และ ESP32-P4 จริงแล้ว ยังไม่ได้ลองบนมือถือ

ทดสอบกับโมเดลจริง แม้เสียงตัวเองเบาลง 26 dB ก็ถูกถอดเป็นภาษาไทยแล้วแปลซ้ำวน) และพูด "หยุดแปล" ไม่หยุด (โมเดลได้ยิน "หยุดแปล" สั้นๆ เป็น "You" + "แปล") • ตอนนี้: บัฟเฟอร์เสียงคงที่ 0.4 วิ, แปลแบบผลัดกันพูด (คำแปลรอจนคุณพูดจบ และไม่ส่งเสียงไมค์ให้โมเดลระหว่างพูดคำแปล), หยุดได้ด้วยการเรียกชื่อผู้ช่วย (คำปลุก) / คำหยุดทั้งที่ได้ยินและในคำแปล ("Stop translating") / ปุ่ม • หน้าจอโหมดภาษาใหม่ (ปุ่ม 💬 บนหน้าหลัก หรือ ตั้งค่า → หน้า 3): ล่าม (เลือก 2 ภาษา, เริ่ม, สลับทิศ, หยุด, ซับสองฝั่ง + ใครกำลังพูด), สอนภาษา (เริ่ม / ฝึกออกเสียง / ทบทวน / จบ — ส่งถึงผู้ช่วย), จดประชุม (เริ่ม / หยุด + ข้อความสด, สรุป / รายการ) • เปิดเองเมื่อเริ่มโหมดด้วยเสียง • แปลช้า/ขาดบน hotspot มือถือ = เน็ต: ล่ามสตรีมเสียงสองทางตลอด แต่ TCP window ของ framework 5.7 KB ได้แค่ ~30 KB/s ต่อทิศที่ความหน่วง 150–200 **Flasher ตรวจการ์ด SD + ปุ่มฟอร์แมต (T237, บอร์ด ESP32-S3 + ESP32-P4; Flasher .exe 2.2.9 / .apk 2.1.8)** — การ์ด SDXC 64–128 GB มาจากโรงงานเป็น exFAT ซึ่งบอร์ดอ่านไม่ได้ (FatFs ไม่มี exFAT; ขนาดการ์ดไม่ใช่ปัญหา FAT32 ได้ถึง 2 TB) และเดิมบอร์ดบอกแค่ "ไม่มีการ์ด" • เฟิร์มแวร์อ่าน boot sector ของการ์ดแม้ mount ไม่ได้ และตอบคำสั่งใหม่ `sdinfo` (สถานะ ok / none / unreadable / error, ระบบไฟล์, ขนาด, cluster, ที่ว่าง) • Flasher: เครื่องมือ → 💾 ไฟล์ SD แสดง "ใช้งานได้ — ไม่ต้องฟอร์แมต" / "ต้องฟอร์แมต: การ์ดเป็น exFAT" / "ไม่พบการ์ด" / "การ์ดมีปัญหา" และปุ่ม 🧹 ฟอร์แมต (ยืนยันก่อน) ส่ง `sdformat confirm`: บอร์ดรีสตาร์ทแล้วฟอร์แมตตอนบูตเป็น FAT32 cluster 32 KB — การ์ดที่อ่านไม่ได้ก็ได้ — Wi-Fi / API key ยังอยู่ แล้ว Flasher แสดงผล • ยังไม่ได้ลองกับการ์ด exFAT บนบอร์ดจริง

**เลือกหน้าหลักได้: คลื่นเสียง หรือ ดวงตา (T236, SenseCAP Watcher + Waveshare 1.54)** — ตั้งค่า → หน้าจอ → หน้าหลัก แตะสลับได้ทันที (console: `set facetheme wave` / `eyes`) • ทั้งสองแบบอยู่ในเฟิร์มแวร์ตัวเดียว ดวงตาเพิ่มแค่ ~6 KB ช่อง app 5 MB ยังว่าง ~210 KB • บนจอ 240×240 ดวงตาย่อเหลือ 0.72 เท่าให้อยู่ในจอกลมของ Watcher • โหมดดวงตา แตะกลางจอ = แตะปกติ (หยุด / ปลุก) และไมค์ปิดจะเห็นไอคอนไมค์แดงใต้ดวงตา • ยังไม่ได้ลองบนบอร์ดจริง

**SenseCAP Watcher ตรวจกับผลสแกนบอร์ดลูกค้า + Flasher .exe 2.2.8 (T235)** — ช่อง Type-C ของ Watcher ต่อ ESP32-S3 ผ่านชิป CH342 ไม่ใช่ USB ในตัวชิป • เฟิร์มแวร์ Watcher จึงคุยทาง UART0 (115200) แล้ว Studio และ Flasher มองเห็นบอร์ดและตั้ง Wi-Fi / API key ผ่านสายได้ • สัญญาณ "เสียบ USB" จาก IO expander เป็น LOW เมื่อเสียบ (เดิมอ่านกลับขั้ว) • สแกนบอร์ดของ Flasher ลองขา I2C ของบอร์ดที่รู้จักก่อน: ผ่านชิปแปลง USB แต่ละคู่ใช้ ~1.5 วิ ขาของ Watcher อยู่ท้ายสุดจนหมดเวลา 30 วิ รายงานเลยบอกว่าไม่ตรงบอร์ด • ชิป, flash 32 MB, PSRAM 8 MB และทุกขาในผลสแกนตรงกับเฟิร์มแวร์ • ยังไม่ได้ลองบน Watcher จริง

**ESP32-P4 ไม่มีการ์ด SD + Flasher .exe 2.2.7 / .apk 2.1.7 / Studio (T234)** — ถ้า P4 มีการ์ด SD รหัส Wi-Fi และ API key จะเก็บในการ์ด (เข้ารหัส) ถอดการ์ดออกบอร์ดจะเหลือแค่ชื่อ Wi-Fi • ตอนนี้จอบอกชัดว่า "รหัส Wi-Fi และ API Key เก็บอยู่ในการ์ด SD ที่ถอดออก — เสียบการ์ดกลับแล้วรีสตาร์ต หรือแตะไอคอนเฟืองเพื่อใส่ใหม่" และในเมนู Wi-Fi เครือข่ายเดิมขึ้น "ยังไม่มีรหัสผ่าน แตะใส่" แล้วถามรหัส (เดิมแตะแล้วแค่ลองต่อด้วยรหัสว่างซ้ำ) • ไม่มีการ์ด (หรือไม่มี `avatar/robot.pak`) หน้าหลักจะแสดงดวงตาเด้งๆ แบบบอร์ดอื่นตามสีตาที่ตั้งแทนหุ่น พร้อมข้อความบอกเหตุผล • Flasher .exe, Flasher .apk และ Studio ลบ + เขียน + ตรวจ flash ทีละ 1 MB: แถบขยับตั้งแต่วินาทีแรก ("ติดตั้งใหม่ทั้งหมด" ของ P4 15.8 MB เดิมนิ่งที่ 0 % 34 วิ ดูเหมือนค้าง) และเขียนเร็วขึ้น

**บอร์ดใหม่: Seeed SenseCAP Watcher W1-A จอกลม 1.45" 412×412 (T233)** — เฟิร์มแวร์ของตัวเอง (`-factory-watcher.bin` / `-app-watcher.bin`) ใช้หน้าจอแบบ smartwatch 240×240 ชุดเดียวกับ Waveshare 1.54 (หน้าคลื่นเสียงแทนดวงตา) ขยายวางกลางจอกลม • หมุน knob = ปรับเสียงผู้ช่วยทีละ 5 % • กดปุ่ม knob สั้น = คุย / ย้อนกลับ, ค้าง 1.5 วิ = เมนูตั้งค่า, ค้าง 5 วิ = ปิดเครื่อง • ลำโพง ES8311 + ไมค์ ES7243E, ช่อง microSD, ไฟ RGB, วัดแบต • ไม่มีหน้าปัดรถ, ยังไม่ใช้กล้อง Himax • **build ผ่านแล้ว ยังไม่ได้ลองบนบอร์ดจริง** — ทัชบนบอร์ดนี้ยังไม่แน่ใจ (ใช้ knob แทนได้ทุกอย่าง) • Flasher .exe 2.2.6 สแกนแล้วบอกได้ว่าเป็น SenseCAP Watcher (จาก IO expander TCA9555 / codec ES8311 บนขา 47/48) และ .apk 2.1.6 มีรุ่นนี้ให้เลือก (wiki 28)

**บอร์ดใหม่ Waveshare ESP32-S3-Touch-LCD-1.54 (จอ 240x240) หน้าตาเป็นวงคลื่นเสียง (T230)** — มีเฟิร์มแวร์ของตัวเอง (`-factory-ws154.bin` / `-app-ws154.bin`) • หน้าหลักแทนดวงตาเป็นไมค์ในวงกลมเรืองแสงกลางจอ มีแสงแตกรอบวง และคลื่นไหลออกไปสองข้าง (ซ้ายฟ้า ขวาชมพู) บนพื้นหลัง nebula มีดาวกะพริบ • จอใช้ gamma 2.5 (ค่าโรงงาน 2.2 สีซีด — console `lcd test` = หน้าทดสอบเทียบค่าจอ) — เราพูดฝั่งซ้ายขยับ AI พูดฝั่งขวาขยับ • แตะไมค์ = เปิด/ปิดไมค์ • เซนเซอร์ QMI8658 หมุนภาพตามท่าวางบอร์ด เขย่า = แตะจอ หยิบขึ้น = ปลุกจอนาฬิกา • ปุ่ม VOL− / VOL+ ปรับเสียง AI (ค้าง VOL− = เมนู, ค้าง VOL+ = ไมค์), PWR = แตะ, ค้าง 3 วินาที = ปิดเครื่อง • วงคลื่นใหญ่เกือบเต็มจอ 240x240 และไม่มีซับไตเติลบทสนทนา (ข้อความของบอร์ดเองยังขึ้น) • ไอคอนซ่อนอยู่ แตะจอแล้วแท็บโค้ง 4 มุมขึ้นมา 5 วินาที (Wi-Fi, ตั้งค่า, แบต, กระดิ่ง) • ปุ่ม PWR ก็เปิด/ปิดไมค์ได้ (ปิดแล้วเป็นสีเทา ไมค์มีขีดแดง) • ปัดจอเพื่อเปิดเครื่องเล่นวิทยุ / เพลง • บอร์ดนี้ไม่มีหน้าปัดรถ / OBD-II • ทุกหน้าวาดเต็มจอ 240x240 แบบ smartwatch: หน้าตั้งค่าเป็นไอคอนกลมใหญ่ เมนูเป็นแถวสองบรรทัด นาฬิกาพักจอ 7 แบบเต็มจอ ส่วนเมนู / การ์ดแสดงแบบย่อ • Flasher .exe 2.2.5 / .apk 2.1.5 รู้จักบอร์ดนี้ (wiki 27)

**สแกนบอร์ดเจอชิปจริงและบอกรุ่นบอร์ดที่ยังไม่รองรับ (T228, Flasher .exe 2.2.3)** — บอร์ด Waveshare ESP32-S3-Touch-LCD-1.54 เคยได้ผล "ไม่พบชิปบนสาย I2C" เพราะมีชิปตอบที่อยู่สงวนที่ตัวสแกนใช้ตรวจว่าสายถูกดึงต่ำ ทั้งสายเลยถูกข้าม ตอนนี้ถือว่าเป็นสาย I2C เมื่อทั้งสองขาอยู่ที่ระดับสูงตอนว่าง และที่อยู่ต้องตอบ 3 ครั้งติดถึงนับ • รายงานบอกชิปที่เจอเป็นคำ (codec, ADC ไมค์, ทัช, IMU …) และบอกชื่อบอร์ดที่รู้จักแต่ยังไม่มีเฟิร์มแวร์ (บอร์ดนี้: ES8311 + ES7210 ที่ SDA 42 / SCL 41) แม้ล้างเฟิร์มแวร์เดิมแล้ว • การตรวจก่อนแฟลชใช้วิธีเดียวกัน บอร์ดของเราที่มีชิปแบบนี้จะไม่ถูกปฏิเสธผิดๆ

**Flasher ไม่ค้างกับบอร์ดที่รันเฟิร์มแวร์อื่น (T227, Flasher .exe 2.2.2)** — บอร์ดที่รันเฟิร์มแวร์อื่น (เช่น XiaoZhi บน Waveshare ESP32-S3-Touch-LCD-1.54) ไม่อ่านคำสั่งทาง USB เดิมทำให้ Flasher บน Windows ค้าง 2 วินาทีทุกคำสั่งและเชื่อมต่อ-หลุดวนไปเรื่อยๆ ตอนนี้ค้างการเชื่อมต่อไว้ ขึ้น "● เชื่อมต่อแล้ว · บอร์ดไม่รับคำสั่ง" (log ของบอร์ดยังขึ้น) และส่งคำสั่งจาก thread แยก หน้าต่างไม่ต้องรอพอร์ตอีก • สแกนบอร์ดบอกเฟิร์มแวร์ที่อยู่ในบอร์ดและรุ่นบอร์ดที่เฟิร์มแวร์นั้นประกาศ (เช่น "xiaozhi 2.0.5 · บอร์ด waveshare-s3-lcd-1.54")

**กล่องตัวเลขลอย (T226, ES3C28P / ES3C35P + ESP32-P4)** — ตอน AI พูดตัวเลขสำคัญ (เงินดอลลาร์/บาท, %, R, จำนวนไม้ TP / SL, องศา, ระยะทาง, นาที, ลิตร, เวลา) บอร์ดดึงจากคำพูดเอง (ไม่เพิ่ม tool ไม่เพิ่ม token) แล้วโชว์เป็นกล่องโปร่งแสงใต้ดวงตา พร้อมไอคอน (เหรียญ ลูกศร เป้า ป้ายหยุด เทอร์โมมิเตอร์ นาฬิกา ...) สีเขียว = บวก แดง = ลบ ค้างไว้ 9 วินาทีหลังตัวเลขตัวสุดท้ายแล้วจางหาย · แสดงทีละอย่าง: กล่องขึ้น subtitle ซ่อน กล่องหาย subtitle กลับมา (กล่องอยู่ที่ของ subtitle ไม่ทับดวงตา) (P4 ที่ไม่มี subtitle กล่องลอยอยู่บนหุ่นยนต์) — ฟังตัวเลขไม่ทันก็อ่านได้ ไม่ต้องให้ AI พูดใหม่

**คาดการณ์ล่วงหน้าเห็นกรอบรายวันและผลงานตัวเอง (T217, ES3C28P + ESP32-P4)** — เมื่อระบบเฝ้ากราฟปลุก AI ตอนนี้ AI เห็นแท่งรายวัน (D1 จาก TradingView อ่านวันละครั้ง), สูง/ต่ำของวันนี้และราคาอยู่ตรงไหนของกรอบวัน, สูง/ต่ำของเมื่อวานและสัปดาห์ก่อน (PDH / PDL / PWH / PWL) พร้อมระยะเป็น ATR และผลงานของตัวเอง: 24 ชม.ล่าสุด (รวมถึงเพิ่งชน SL ติดกันกี่ครั้ง) และ 30 วัน (เก็บรายวันใน `antic_track.json`) พร้อมบรรทัดเดียวกับแอป "ถ้าช่วงนี้ชน SL บ่อย ให้ระวังมากขึ้น" · สตรีมราคาสดปลุก AI เมื่อราคาแตะ PDH / PDL / PWH / PWL ด้วย — ทำให้บอร์ดใกล้เคียงระบบเฝ้ากราฟของแอป Android

**หน้าประวัติคาดการณ์ไม่ค้างแล้ว (T218, ES3C28P + ESP32-P4)** — การ์ดสถิติของหน้าประวัติเคยอ่านไฟล์ประวัติทั้งไฟล์จาก SD ใหม่ทุกเฟรม ทำให้จอหน่วง จิ้มไม่ค่อยไป และทำให้เครือข่ายขาดหน่วยความจำ (สตรีมราคาหลุดพร้อม `esp-aes: Failed to allocate memory`) ตอนนี้อ่านใหม่เฉพาะเมื่อไฟล์เปลี่ยน · เหตุผลบนการ์ดแสดงเต็ม · บนจอ 2.8" ช่องชนะ/แพ้ ป้ายแจ้งเตือน และแถว เข้า/SL/TP ไม่ทับกันแล้ว

**ถาม AI "สรุปผลคาดการณ์" ไม่ทำให้เครือข่ายหลุดอีก (T219, ES3C28P + ESP32-P4)** — การสรุปผลเคยโหลดเหตุผลของ AI ทั้ง 240 ครั้งเข้าหน่วยความจำภายในพร้อมกัน (~51 KB ต่อการถาม 1 ครั้ง ซึ่งเป็นหน่วยความจำเดียวกับที่การเชื่อมต่อเข้ารหัสต้องใช้) ตอนนี้นับเหตุผลทีละรายการแล้วเก็บไว้แค่ไม่กี่รายการที่ต้องพูด — คำสรุปเหมือนเดิมทุกคำ

**ESP32-AI Flasher สแกนบอร์ด ESP32 ได้ทุกรุ่น (T220, Windows .exe 2.2.0)** — ถ้าซื้อบอร์ดรุ่นอื่นมาแล้วใช้ไม่ได้ ให้กด "🔍 สแกนบอร์ด" ในแท็บแฟลช (ใส่ชื่อรุ่นหรือลิงก์ร้านค้าในช่องเหนือปุ่มได้) โปรแกรมจะอ่านชนิดชิป ขนาด flash จริง PSRAM ขาที่ต่อวงจรอยู่บนบอร์ด ชิปบนสาย I2C (เช่น codec เสียง ทัช จอ OLED ชิปจ่ายไฟ) และข้อความตอนบูตของเฟิร์มแวร์เดิม โดยไม่เขียนอะไรลงบอร์ด แล้วบอกว่าใช้ได้หรือไม่เพราะอะไร พร้อมบันทึกไฟล์รายงานไว้ที่ `Documents\ESP32-AI-Flasher\board-scans` ให้ส่งมาเพื่อทำเฟิร์มแวร์ให้ตรงบอร์ด · Flasher ไม่ยอมแฟลชไฟล์ที่ใหญ่เกิน flash ของบอร์ดแล้ว (เดิมบอร์ด 8 MB แฟลช "สำเร็จ" แต่ไม่บูต) และรู้จัก ESP32 รุ่นแรกกับบอร์ดที่ใช้ชิป USB CH340 / CP2102 · ก่อนแฟลช Flasher ถามชิปของบอร์ดรุ่นนั้นบนขาของมันก่อน ถ้าไม่ตอบจะไม่แฟลช (เช่น จอ 3.5" รุ่นอื่นที่ใช้ชิปจอ AXS15231B เคยได้เฟิร์มแวร์ ES3C35P แล้วจอเป็นจุดสี) และรายงานสแกนบอกได้ว่า "ติดตั้งเฟิร์มแวร์ของอีกบอร์ดอยู่"

**บอร์ดใหม่: Guition JC3248W535 (ESP32-S3 จอ 3.5" ชิปจอ AXS15231B) (T221)** — มีเฟิร์มแวร์ของตัวเองแล้ว (`-factory-jc3248w535.bin` / `-app-jc3248w535.bin`) จอ ทัช ลำโพง การ์ด SD และแบตใช้ได้ บอร์ดนี้**ไม่มีไมโครโฟน** ถ้าจะสั่งด้วยเสียงให้ต่อไมค์ I2S (INMP441) ที่ขา IO15 (SCK) / IO16 (WS) / IO7 (SD) ไม่ต่อไมค์ก็ยังพิมพ์คุยจากแอป ฟังวิทยุ และดูข้อมูลได้ · Flasher เลือกบอร์ดนี้ให้เองจากชิปทัชของมัน · ยังไม่ได้ทดสอบกับบอร์ดจริง (wiki 26)

**บทเรียนภาษาพูดไทยเป็นหลัก การ์ดคำศัพท์ตรงจังหวะ (T224, ES3C28P + ESP32-P4)** — ผู้เรียนที่ยังไม่วัดระดับหรือระดับ A1–A2 ครูจะอธิบาย ชม และถามเป็นภาษาไทย ใช้ภาษาที่เรียนเฉพาะคำ/ประโยคที่สอน (ระดับ B: ประโยคสั้นง่าย อธิบายเป็นไทย, ระดับ C: ภาษาที่เรียนเป็นหลัก) • คำใหม่ขึ้นจอก่อนครูพูด (เดิมการ์ดช้าไปหนึ่งคำ ขึ้นหลังผู้เรียนพูดตามแล้ว)

**โหมดล่าม / สอนภาษาไม่หลุดกลางคัน (T223, ES3C28P + ESP32-P4)** — ระหว่างบทเรียน กติกาการสอนอยู่ใน system prompt ของผู้ช่วยตลอด (เดิมมากับผลของ tool ซึ่ง sliding window ของ context ตัดทิ้งภายในไม่กี่นาที AI เลยเลิกสอน) • เริ่ม/จบบทเรียนจะเปิด session ใหม่โดยพาบทสนทนาล่าสุดไปด้วย • บีบ context ที่ 15,500 → 12,500 token (เดิม 13,000 → 10,000 เหลือที่ให้บทสนทนาแค่หลักร้อยเหนือ prompt ~9.8k) • หลังออกจากโหมดล่าม เสียงท้ายที่ค้างในบัฟเฟอร์เคยทำให้บอร์ดค้าง "กำลังพูด" และปิดไมค์ → ตอนนี้เล่นออกเอง และคำแปลเล่นทันทีที่มาถึง • log ทาง serial บอกว่าแต่ละโหมดได้ยินและแปลว่าอะไร

**จอสีกลับด้าน / พื้นหลังเป็นสีขาว (T222, Flasher .exe 2.2.1 / .apk 2.1.4)** — จอของบอร์ดรุ่นเดียวกันบางล็อตต้องตั้งค่าสีกลับกัน ในแท็บตั้งค่า หมวด "เครื่อง" กดปุ่ม "🌓 สลับสีจอบอร์ด" สีจะสลับทันทีและบอร์ดจำค่าไว้ (บนบอร์ดเอง: ⚙ → หน้าจอ & พักหน้าจอ → สลับสีจอ)

**บันทึกตรวจย้อนการคาดการณ์ล่วงหน้า (T216, ES3C28P + ESP32-P4)** — ทุกครั้งที่ระบบเฝ้ากราฟปลุก AI บอร์ดที่มี SD card จะเขียน 1 บรรทัดลง `agent/antic_audit/YYYY-MM-DD.jsonl` (เก็บ 30 วัน): เหตุการณ์ที่ปลุก, ทิศโครงสร้าง ตำแหน่งในกรอบ และแนวรับ-แนวต้านทุกไทม์เฟรมตามที่ AI เห็น, SL/TP วางอยู่ที่แนวไหน และเหตุผลเต็มของ AI — ตรวจย้อนได้ว่า "ขายที่แนวต้าน" จริงไหม (`antic_audit.py` บน PC จับคู่กับผล TP/SL)

**ตัวหนังสือใหญ่ขึ้น + การ์ดสอนภาษาแบบมีสี (T215, ES3C28P)** — ฟอนต์ไทยบนจอ 2.8" เป็น TH SarabunPSK ตัวหนา 24 / 28 px (เดิม TH Sarabun New 20 / 26 px ตัวเล็กสูงแค่ 7 px) ขอบคมขึ้น ตัวละติน/ซีริลลิกเป็น Noto Sans ตัวหนาตาม · บทเรียนมีการ์ดของตัวเอง: คำศัพท์ในกรอบสี (ญี่ปุ่น/จีน/เกาหลีขยาย 2 เท่า) พร้อมคำอ่าน ความหมาย และจุดรอบทบทวน · ฝึกพูดมีแถบความคืบหน้า ไมค์เต้นตามจังหวะ วงแหวนคะแนน · เหรียญระดับกับช่องไอคอน (วันต่อเนื่อง คำศัพท์ ต้องทบทวน ออกเสียง) · สรุปผลมีดาวและคะแนนรายประโยค (P4 ยังเป็นการ์ดข้อความเดิม)

**สอนภาษา (T214, ES3C28P + ESP32-P4)** — "สอนภาษาญี่ปุ่นหน่อย" ผู้ช่วยเป็นครู บอร์ดเก็บข้อมูลผู้เรียนใน SD card: ระดับ (A1–C2) เรียนต่อเนื่องกี่วัน คลังคำศัพท์ไม่เกิน 300 คำพร้อมรอบทบทวน (1, 2, 4, 8, 16 วัน) • คำ/ประโยคใหม่ขึ้นการ์ดบนจอ (ES3C28P แสดงตัวอักษรจริง P4 แสดงคำอ่าน) • ทบทวนคำศัพท์แล้วบอร์ดเลื่อนรอบให้ • **ฝึกออกเสียง**: บอร์ดสลับไปใช้ Gemini 3.5 Transcribe Live ภาษานั้น ขึ้นประโยคทีละข้อ แล้วให้คะแนนจากสิ่งที่ได้ยินเทียบกับประโยคต้นแบบ (ลองได้ 2 ครั้ง แตะจอ = ข้าม) จากนั้นส่งคะแนนให้ผู้ช่วยสอนเฉพาะประโยคที่ได้คะแนนต่ำ • ฝึกฟัง: ซ่อนข้อความของผู้ช่วย • คะแนนวัดว่าพูดแล้วเครื่องถอดความได้ตรงแค่ไหน ไม่ได้วัดสำเนียง • ยังไม่ได้ลองด้วยเสียงพูดจริง

## 🧪 การทดสอบ

โมดูลที่ไม่ผูกกับฮาร์ดแวร์ (ความจำ, tools, ตัวตั้งเวลา, รายการงาน, บุคลิก, model fallback, เครื่องคิดเลข, แปลงหน่วย …) ทดสอบบน PC:

```bat
host_tests\run_tests.bat
```

77 ชุดทดสอบ · 2,945 checks · ต้องมี Visual Studio Build Tools (`cl.exe`) และรัน `pio run` ก่อน 1 ครั้ง (เพื่อดึง ArduinoJson)
Linux / macOS / CI: `bash host_tests/run_tests.sh` (g++ หรือ clang++)

แอปมือถือมี unit tests ของตัวเอง 58 ข้อ (console/การตั้งค่า, เชื่อมบอร์ดรวม handshake Wi-Fi จริง, อ่าน Google Maps + ตัวแฟลชที่ทดสอบกับ ROM bootloader ของ ESP32-S3 จำลอง + flash เสมือน 16 MB):
`cd tools/mobile_app && ./gradlew :esp32:testDebugUnitTest` · แอป build ได้โดยไม่มี warning Kotlin · PC เครื่องใหม่หรือลง Windows ใหม่จะได้กุญแจเซ็น
debug ใหม่ → ถอนแอปเดิมบนมือถือครั้งเดียว หรือคัดลอก `~/.android/debug.keystore` เดิมกลับมา ([wiki 17](wiki/17-Mobile-Flasher.md))
· Gradle daemon ("OpenJDK Platform binary" ใน Task Manager) ปิดเองหลังว่าง 15 นาที หรือสั่ง `gradlew --stop` ให้ปิดทันที

## 🔒 ความปลอดภัย & ความเป็นส่วนตัว

**รหัส Wi-Fi และ API key เก็บอยู่ที่ไหน**

| ที่ | มีความลับไหม |
|---|---|
| ซอร์สโค้ดใน repo นี้ | **ไม่มี** — ความลับพิมพ์ใส่บนเครื่อง (เมนูทัชหรือ Studio) ไม่ได้อยู่ในโค้ด |
| `include/secrets.h` (ค่าเริ่มต้นตอน build, ไม่บังคับ) | มีเฉพาะถ้าคุณกรอกเอง — ไฟล์นี้ถูก **git-ignore** จึงไม่ถูกอัปโหลด ส่วน `secrets.example.h` มีแค่ค่าตัวอย่าง |
| ไฟล์เฟิร์มแวร์ที่ build แล้ว (`.pio/`) | มีเฉพาะถ้าใช้ `secrets.h` — โฟลเดอร์ build ถูก git-ignore |
| การ์ด SD — `agent/secrets.json` (ถ้าไม่ได้ใส่การ์ด: NVS ในแฟลชบอร์ด) | **มี แต่เข้ารหัส** AES-256-GCM ด้วยกุญแจที่คำนวณจาก MAC + eFuse unique ID ของชิปตัวนั้น (`src/app/SecretBox.*`) — ไฟล์เปิดได้เฉพาะบอร์ดที่สร้าง (ย้ายการ์ดไปบอร์ดอื่น = ตั้งค่าใหม่ด้วย `ai-setup.txt`) เปิดการ์ดบนคอมพิวเตอร์จะไม่เห็นรหัส และ `ai-setup.txt` ถูกเขียนทับแล้วลบทันทีหลังอ่าน สำเนาแบบข้อความธรรมดาเดิมถูกล้างอัตโนมัติครั้งเดียว (รวมสำเนาที่ไดรเวอร์ Wi-Fi เก็บเอง ซึ่งปิดแล้วด้วย `WiFi.persistent(false)`) |

- ไม่ใช่ flash encryption เต็มรูปแบบ: คนที่ได้ทั้งบอร์ด**และ**เฟิร์มแวร์นี้ไปยังคำนวณกุญแจได้ ควรใช้ API key แยกเฉพาะบอร์ดนี้ และเปลี่ยน key ถ้าบอร์ดหาย
- เฟิร์มแวร์และ Studio **ไม่เคยพิมพ์** API key หรือรหัส Wi-Fi ออกมา — `config` แสดงแค่ตัวย่อที่ซ่อนแล้วและ `secretsSealed` ไฟล์ตั้งค่าที่ส่งออกไม่มีความลับ ไฟล์เสียงที่อัด (`recordings/`) ถูก git-ignore
- ขณะเปิดไมค์ เสียงจะถูกส่งไปที่ Gemini API ของ Google ส่วนความจำและโน้ตอยู่ใน SD/แฟลชของบอร์ด
- Gemini API key ส่งใน header `x-goog-api-key` (ไม่อยู่ใน URL) และ tools ข้อมูลใช้เฉพาะ HTTPS ที่ตรวจใบรับรอง — `http://` ธรรมดาถูกปฏิเสธ

## 🧑‍💻 สำหรับนักพัฒนา

- **Fork & build:** `pio run` build ได้จาก clone ใหม่โดยไม่ต้องมี `secrets.h` — ค่าตั้งค่าอยู่ใน NVS (`src/app/Settings.*`) key ของคุณจึงไม่เข้าไปอยู่ในซอร์สโค้ด
- **เพิ่ม tool:** ประกาศใน `AgentTools::addDeclarations` (`src/agent/AgentTools.cpp`) tool ที่ใช้เน็ตใส่ใน `src/agent/WebToolsExtra.cpp` และวาด `CardData` (ดู [wiki/11](wiki/11-Data-Tools-and-Cards.md))
  tool ที่ใช้ไม่บ่อยใช้ `box(...)` แทน `declare(...)` ได้ (อาร์กิวเมนต์เดียวกัน) — กลายเป็นบรรทัดสั้นๆ ในคำอธิบายของ "กล่องเครื่องมือ" `use_tool` เสียโทเคนทุกเทิร์นราว 1 ใน 3 ของการประกาศเต็ม และ AI เรียกด้วย `use_tool {name, args}` (T209, ES3C28P + ESP32-P4 — [wiki/09](wiki/09-Assistant-Profiles-and-Tools.md))
- **ทดสอบไม่ต้องมีบอร์ด:** `host_tests\run_tests.bat` — บนบอร์ดเรียก tool ทุกตัวได้จากแท็บ 🧰 ใน Studio หรือ serial (`tool <name> {json}`)
- **ดูบทสนทนากับ Live API:** พิมพ์ `trace on` ใน serial → ขึ้นบรรทัด `[Trace]` ทุกข้อความจากเซิร์ฟเวอร์ (transcript, การเรียก tool, `generationComplete` / `turnComplete` — ก้อนเสียงแค่นับจำนวน) และทุกข้อความ JSON ที่บอร์ดส่ง (`trace off` ปิด, ไม่บันทึกค่า) — ใช้หาสาเหตุ AI ตอบซ้ำ 2 รอบหลังเรียก tool ([T071](wiki/07-Troubleshooting-Log.md))
- **ออก Release:** แก้ `FIRMWARE_VERSION` ใน `src/app/AppConfig.h` และ `firmware-p4/src/app/AppConfig.h` (เลขเดียวกัน: release เดียวมีไฟล์ทั้งสองบอร์ด T155) → commit → `git push` → `python tools/publish_release.py` สคริปต์จะ build ไฟล์ factory (`tools/make_release.py`) สร้าง Release แบบร่าง แนบไฟล์ factory และไฟล์ OTA `-app.bin` (พร้อม `.sha256`) และแอปมือถือ `PersonalAIBot-Mobile.apk` (build ให้อัตโนมัติเมื่อเครื่องมี Android SDK ไม่ต้องสร้าง keystore — เซ็นด้วย debug key ของ SDK เว้นแต่สร้าง keystore เองด้วย `--create-keystore`) เผยแพร่ แล้วดาวน์โหลดกลับมาเทียบ sha256 โดยรัน host tests ก่อนเผยแพร่เสมอ (`--skip-tests` ใช้เฉพาะเครื่องที่ไม่มี compiler) — Release ของ repo นี้เป็นแบบ **immutable** เผยแพร่แล้วแก้ไฟล์หรือใช้ชื่อ tag ซ้ำไม่ได้ ทุกครั้งต้องใช้เลขเวอร์ชันใหม่ (`--dry-run` = ตรวจอย่างเดียว) รหัส Wi-Fi และ API key ไม่ต้องใช้กุญแจ release เลย: เก็บใน SD card ของบอร์ดแบบเข้ารหัสด้วยกุญแจที่คำนวณจากชิปของบอร์ดนั้น (เปลี่ยนการ์ดหรือเปลี่ยนบอร์ด = ตั้งใหม่) และอัปเดต OTA แล้วยังอยู่ครบ **ทางเลือก — เซ็นอัปเดต OTA:** ESP32-AI Studio แท็บ 🔧 เฟิร์มแวร์ → **🔑 สร้างกุญแจ** (หรือ `pip install cryptography` → `python tools/ota_keygen.py`) → commit `src/app/OtaPublicKey.h` และสำรองกุญแจส่วนตัวที่สคริปต์บอกที่อยู่ไว้ (อยู่นอก repo) — บอร์ดที่ build พร้อมกุญแจนั้นจะติดตั้งเฉพาะอัปเดตที่เซ็นด้วยกุญแจนี้ ([wiki 13](wiki/13-OTA-Update.md))
- **CI:** [`.github/workflows/firmware.yml`](.github/workflows/firmware.yml) ทำแบบเดียวกันบน GitHub Actions แต่ตอนนี้ตั้งเป็นกดรันเองเท่านั้น (*Actions → Firmware → Run workflow*) และ job ออก release จะรอ job host-tests ผ่านก่อน — `tools/make_release.py` ไม่ยอมทำงานถ้า `include/secrets.h` มีค่าจริง และสแกนไฟล์หาสิ่งที่หน้าตาเหมือน API key

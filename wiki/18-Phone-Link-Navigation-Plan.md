**ผู้ใช้เลือก (2026-10-20):** ช่องทาง **Wi-Fi + USB** (BLE ไม่ทำ) · เส้นทางจาก **Google Maps บนมือถือ** · **AI บนบอร์ดพูดเตือนก่อนเลี้ยว** ·
สั่งมือถือได้แค่ **Google Maps** (นำทาง / หยุด) · มือถือทดสอบ **HONOR X9d** และ **Samsung S22 Ultra**

## วิธีใช้ (สิ่งที่ทำแล้ว)
1. **แฟลชเฟิร์มแวร์รุ่นนี้** (หรือรุ่น release ถัดไป) และติดตั้งแอปมือถือ Personal AI Bot รุ่นใหม่ (หน้าบอร์ด ESP32 → แท็บนำทาง; T088)
2. **จับคู่ครั้งเดียว:** เสียบสาย USB เข้าบอร์ด เปิดแอป แท็บบอร์ดขึ้น "เชื่อมต่อแล้ว" → แอปส่ง token ให้บอร์ด (log บอร์ด `OK phone paired`)
   — บอร์ดจะประกาศ tool `navigate` ให้ AI ตั้งแต่เซสชันถัดไป
3. แท็บ **🧭 นำทาง** ในแอป: เปิดสิทธิ์ทุกข้อในรายการ (ตำแหน่ง, แจ้งเตือน, **อ่านการแจ้งเตือน**, **แสดงทับแอปอื่น**, ไม่จำกัดแบต) → กด **▶ เริ่มส่ง**
   - Android 13+ กับแอปที่ติดตั้งจากไฟล์: ถ้าสวิตช์ "อ่านการแจ้งเตือน" / "แสดงทับแอปอื่น" กดไม่ได้ → ข้อมูลแอป → ⋮ → **อนุญาตการตั้งค่าที่ถูกจำกัด**
   - HONOR: แบตเตอรี่ → เปิดแอป → จัดการเอง · Samsung: แบตเตอรี่ไม่จำกัด + เอาออกจากแอปที่ sleeping
4. **ในรถ:** เปิด Hotspot มือถือ ตั้ง Wi-Fi ของบอร์ดเป็น Hotspot นี้ (บอร์ดใช้เน็ตจากมือถืออยู่แล้ว) → บอร์ดต่อเข้าหามือถือเองที่ gateway
   · **ที่บ้าน:** มือถือกับบอร์ด Wi-Fi เดียวกันก็ได้ (แอปประกาศตัวทาง UDP) · หรือเสียบ USB ก็ได้
5. หน้าปัด → แหล่งข้อมูล **"GPS มือถือ"** = ความเร็วจาก GPS (รถที่ไม่มี OBD) · หรือใช้ OBD/K-Line ต่อไป แถบนำทางขึ้นบนหัวหน้าปัดเองเมื่อนำทาง
6. นำทาง: พูด **"นำทางไปเซ็นทรัลเวิลด์"** (มือถือเปิด Google Maps นำทาง) หรือเริ่มใน Maps เอง → จอบอร์ดขึ้นหน้า **นำทาง** (ลูกศร ระยะ คำสั่ง เวลาถึง ความเร็ว)
   · AI พูด **"อีก 300 เมตร เลี้ยวขวาเข้า ถ.พระราม 4"** ก่อนถึงจุดเลี้ยว ~20 วิ · ถาม "อีกไกลไหม" / "ถึงกี่โมง" / "ตอนนี้อยู่ไหน" / "หยุดนำทาง"
7. ลูกศร/ระยะผิด: แท็บนำทางมี **ข้อความล่าสุดจาก Google Maps** — ส่งให้ผู้พัฒนาเพื่อเพิ่มรูปแบบใน `MapsParser`

## Handshake Wi-Fi v2 + ตราประทับต่อบรรทัด (T090)

```
board  hello {"nonce":"<Nb>","fw":"4.4.0","v":2}
phone  phone {"t":"hello","app":"2.0.0","nonce":"<Np>"}              ← ยังไม่พิสูจน์อะไร
board  auth {"proof":hmac(token,"board|<Np>")}
phone  phone {"t":"auth","proof":hmac(token,"phone|<Nb>")}
session = hmac(token, "session|<Nb>|<Np>")
ทุกบรรทัดต่อจากนี้: <line>\t<seq>.<32 hex แรกของ hmac(session, "<p|b>|<seq>|<line>")>   (seq นับจาก 0 แยกแต่ละทิศ)
```
- **ทำไม:** v1 แอป (ฝั่งที่เปิดรับการเชื่อมต่อ) ตอบ proof ให้ทุกคนที่ส่ง hello มา → คนใน Wi-Fi เดียวกันประกาศ `PABPHONE` ให้บอร์ดต่อมาหาตัวเอง
  แล้วเอา nonce ของบอร์ดไปขอ proof จากแอปจริง (relay) → บอร์ดเชื่อว่าเป็นมือถือ แล้วส่ง GPS/การนำทางปลอมได้ · v2: แอปพิสูจน์หลังบอร์ด
  + ทุกบรรทัดผูกกับ session key → คนกลางทำได้แค่ส่งต่อ ปลอม/ส่งซ้ำ/สลับลำดับไม่ได้ (เจอ = ตัดการเชื่อมต่อ)
- **ไม่เข้ากันกับรุ่นเก่า:** บอร์ด v2 + แอปเก่า → บอร์ดตัด "the phone app is too old" · แอปใหม่ + บอร์ดเก่า → แอปบันทึก "board's firmware is too old"
  → อัปเดตทั้งคู่ (ทาง USB ไม่เปลี่ยน)
- ทดสอบ: host test `phone_wifi_lines_are_sealed` + `PhoneLinkTest.sealsMatchTheBoard` ใช้ค่าเดียวกัน (= Python hmac),
  `wifiHandshakeThenRequestsBothWays` (บรรทัดที่ไม่มีตรา → ตัดการเชื่อมต่อ ไม่ทำตาม), `oldBoardFirmwareIsToldToUpdate`

## 1. สรุปความเป็นไปได้

| ส่วน | เป็นไปได้ | เหตุผลสั้นๆ |
|---|---|---|
| ส่ง GPS มือถือ → บอร์ด ทาง **USB** | ✅ สูงมาก | มีช่องทางอยู่แล้ว (แอปมือถือ T081 คุย console ได้) — แต่ในรถไม่สะดวก (ดูข้อ 3) |
| ทาง **Wi-Fi** | ✅ สูง | ในรถบอร์ดต้องต่อ hotspot มือถืออยู่แล้วเพื่อใช้ Gemini → มือถือคือ gateway หากันเจอทันที ไม่ต้องตั้งค่าเพิ่ม |
| ทาง **บลูทูธ (BLE)** | ⚠️ กลาง–ต่ำ | S3 มีแค่ BLE (ไม่มี Classic) · **RAM ภายในว่างจริง 39 KB** ตอนคุย AI (ภาพจากผู้ใช้) แต่ BLE ต้อง ≥ 40 KB · ชนกับ ELM327 BLE (wiki 16) · BLE + Wi-Fi ใช้วิทยุตัวเดียวกัน (coexistence) อาจทำเสียง AI กระตุก |
| หน้าปัดแสดง **ความเร็ว/ทิศจาก GPS** (รถที่ไม่มี OBD) | ✅ สูง | เพิ่มแหล่งข้อมูล `phone_gps` ใน `vehicle::SourceId` — โครงรองรับหลายแหล่งอยู่แล้ว |
| **นำทางทีละจุดเลี้ยว** บนจอบอร์ด (ลูกศร + ระยะ + ชื่อถนน + ETA) | ✅ กลาง–สูง | ให้ Google Maps บนมือถือคำนวณเส้นทาง แอปอ่าน "การแจ้งเตือนการนำทาง" ของ Maps แล้วส่งให้บอร์ด — ฟรี ไม่ต้องมี API key แต่รูปแบบข้อความเปลี่ยนได้ตามเวอร์ชัน Maps |
| **แผนที่เต็มจอ** บนบอร์ด | ❌ ไม่แนะนำ (ตอนนี้) | จอ 320×240 · ภาพแผนที่ Google ห้ามจับภาพไปแสดง (เงื่อนไขการใช้) · ไทล์ OSM ใช้ได้แต่มีนโยบายจำกัดการใช้ — ทำได้ภายหลังเป็น "เส้นทาง + จุดของเรา" แบบวาดเอง |
| พูด **"นำทางไป …"** กับบอร์ด → มือถือเปิด Google Maps นำทาง | ✅ สูง | tool ใหม่ของ Gemini → ส่งคำสั่งให้แอป → `google.navigation:q=...` · Android 10+ ห้ามแอปเบื้องหลังเปิดหน้าจอเอง → ต้องได้สิทธิ์ "แสดงทับแอปอื่น" (หรือผูกอุปกรณ์แบบ Companion ตอนใช้ BLE) **ต้องลองบนมือถือจริง** |
| สั่ง **โทร / SMS / เพลง (เล่น-หยุด-ถัดไป) / อ่านแจ้งเตือน / หามือถือ (ให้ดัง) / ไฟฉาย / ความดัง** | ✅ สูง | API ของ Android รองรับ (ต้องขออนุญาตแต่ละอย่าง — แอปติดตั้งเอง ไม่ผ่าน Play Store จึงขอได้) |
| **รับสาย / วางสาย** | ✅ กลาง | `TelecomManager` (สิทธิ์ ANSWER_PHONE_CALLS) — แต่**เสียงโทรศัพท์ไม่ผ่านบอร์ด** (บอร์ดไม่มี Bluetooth Classic/HFP) |
| ส่งข้อความ **LINE / WhatsApp** | ❌ ไม่ได้ | ไม่มี API ให้แอปอื่นส่งแทน (ทำได้แค่เปิดหน้าแชร์ให้ผู้ใช้กดเอง · Accessibility automation ทำได้แต่เปราะ — ไม่แนะนำ) |
| **iPhone** | ❌ (แอปนี้) | iOS ไม่ให้แอปใช้ USB serial และแอปนี้เป็น Android · ถ้าออกแบบช่องทาง Wi-Fi/BLE ให้เป็นกลาง วันหน้าทำแอป iOS แยกได้ |

**สรุป:** ทำได้เกือบทั้งหมด — **Wi-Fi เป็นช่องทางหลักในรถ**, USB สำหรับตั้งค่า/ทดสอบ, BLE เป็นทางเลือกท้ายสุด (เปิดได้เมื่อปิดคำปลุก 1 คำหรือไม่ใช้ OBD BLE)
นำทางใช้ Google Maps คำนวณ บอร์ดแสดง + สั่งด้วยเสียง

### 2.1 ข้อความ (เหมือนกันทุกช่องทาง)
บรรทัดเดียว `<TAG> <json>` แบบ console เดิม (wiki 10) — USB ใช้ได้ทันที, Wi-Fi/BLE ส่งบรรทัดเดียวกัน

| ทิศทาง | ตัวอย่าง |
|---|---|
| มือถือ → บอร์ด | `phone {"t":"hello","app":"1.2","caps":["gps","nav","call","sms","media"],"bat":78}` |
| | `phone {"t":"gps","lat":13.7563,"lon":100.5018,"spd":12.4,"hdg":270,"acc":4,"ts":1792480000}` (1 ครั้ง/วิ) |
| | `phone {"t":"nav","icon":"right","text":"เลี้ยวขวาเข้า ถ.พระราม 4","dist_m":200,"eta":"16:40","left_km":5.4}` / `{"t":"nav","end":true}` |
| | `phone {"t":"result","id":7,"ok":true,"say":"เริ่มนำทางไป เซ็นทรัลเวิลด์ แล้วค่ะ"}` |
| บอร์ด → มือถือ | `PHONE {"id":7,"do":"navigate","to":"เซ็นทรัลเวิลด์"}` · `{"do":"call","who":"แม่"}` · `{"do":"media","act":"next"}` · `{"do":"find"}` |

- **ความปลอดภัย:** ช่องทาง Wi-Fi/BLE ต้อง**จับคู่ครั้งแรก** (บอร์ดแสดงรหัส 6 หลัก พิมพ์ในแอป → เก็บ token) · ข้อความจากมือถือรับเฉพาะชุด `phone ...`
  (ไม่ให้สั่ง `set key` / `reboot` ผ่าน Wi-Fi/BLE) · USB = ผู้ใช้เสียบสายเอง เชื่อได้แบบ console เดิม
- **ไม่ส่งพิกัดออกนอกบ้าน:** พิกัดอยู่ระหว่างมือถือกับบอร์ดเท่านั้น · ส่งให้ Gemini เฉพาะตอนผู้ใช้ถาม ("ตอนนี้อยู่ไหน") เป็นชื่อสถานที่จาก Geocoder ของมือถือ

## 3. ช่องทางการเชื่อมต่อ — ข้อดี/ข้อจำกัด

| | USB (OTG) | Wi-Fi | BLE |
|---|---|---|---|
| ทำงานแล้ว | ✅ (T080–T081) | ยังไม่มี server/ลิงก์บนบอร์ด | บอร์ดเป็น BLE central ให้ ELM327 อยู่แล้ว ยังไม่มีโหมด peripheral |
| หากันเจอ | เสียบสาย | hotspot: บอร์ดต่อ TCP ไป **gateway** (= มือถือ) · Wi-Fi บ้าน: มือถือประกาศ UDP broadcast ให้บอร์ดรู้ IP | สแกนชื่อบอร์ด + จับคู่ |
| RAM ภายในบอร์ด | 0 (ใช้ console เดิม) | ~2–4 KB (socket ธรรมดา ไม่ใช้ TLS ใน LAN) | **~36–40 KB** — ตอนนี้ว่าง 39 KB ระหว่างคุย AI → ไม่พอถ้ายังเปิดคำปลุก 2 คำ |
| ความเร็ว | สูง | สูง | ต่ำ (พอสำหรับ GPS/นำทาง/คำสั่ง ไม่พอภาพ) |
| ในรถ | ❌ มือถือจ่ายไฟให้บอร์ดและชาร์จตัวเองไม่ได้ (ต้องใช้สาย OTG แบบ Y) | ✅ **แนะนำ** — บอร์ดต้องใช้เน็ตจาก hotspot อยู่แล้ว | ⚠️ ใช้ได้ถ้า RAM พอ · เสี่ยงเสียง AI กระตุก (วิทยุ 2.4 GHz ตัวเดียวแบ่งเวลา) |
| มือถือปิดจอ | foreground service ถือพอร์ตต่อได้ | foreground service ถือ socket | foreground service + Companion Device (Android อนุญาตทำงานเบื้องหลังมากกว่า) |

## 4. แผนเป็นเฟส (ทำทีละเฟส ทดสอบบนบอร์ด/มือถือจริงก่อนไปต่อ)

### เฟส 0 — แกนกลาง `PhoneLink` + ข้อความ (ขนาด: M)
- บอร์ด: `src/phone/PhoneLink.{h,cpp}` (parse `phone ...`, สถานะล่าสุด, timeout 5 วิ = หลุด, คิวคำสั่ง `PHONE {...}` + รอ `result`), console รับบรรทัด `phone`
- บอร์ด: logic แยกเป็น header แบบเดิม (`src/util/PhoneProtocol.h`) + **host tests** (parse/ตรวจค่า/timeout/คิว)
- แอป: `LinkService` (foreground service), ส่ง `hello` + `gps` ผ่าน USB ก่อน (ใช้ `BoardLink` เดิม) · ขอสิทธิ์ตำแหน่ง
- **ผ่านเมื่อ:** console บอร์ดพิมพ์ GPS จากมือถือได้ 1 Hz นาน 30 นาที ไม่หลุด · `diag` มี `phone` (ช่องทาง, อายุข้อมูล)

### เฟส 1 — Wi-Fi + GPS บนหน้าปัด (ขนาด: M)
- บอร์ด: `PhoneWifi` — ต่อ TCP ไป gateway:พอร์ตคงที่ (hotspot) หรือ IP จาก UDP broadcast (Wi-Fi บ้าน) · จับคู่รหัส 6 หลัก · ต่อใหม่เองเมื่อหลุด
- แอป: ServerSocket บน hotspot/LAN + UDP broadcast · หน้า "เชื่อมบอร์ด" เลือก USB / Wi-Fi
- บอร์ด: `vehicle::SourceId::PhoneGps` — ความเร็ว (km/h) + ทิศ จาก GPS → หน้าปัดทุกแบบ · เมนูเลือกแหล่ง "มือถือ (GPS)"
- **ผ่านเมื่อ:** ขับจริง: ความเร็วบนหน้าปัดต่างจากมาตรวัดรถ ≤ 5 % · ปิดจอมือถือ 30 นาทีแล้วยังส่ง · เสียง AI ไม่กระตุกเพิ่ม · RAM ภายในไม่ลดเกิน 4 KB

### เฟส 2 — นำทาง (ขนาด: M–L)
- แอป: `NavBridge` (NotificationListenerService) อ่านการแจ้งเตือนนำทางของ Google Maps (`com.google.android.apps.maps`):
  ข้อความจุดเลี้ยว, ระยะ, ETA → แปลงเป็น `icon` จากคำ (เลี้ยวซ้าย/ขวา, ชิด, กลับรถ, วงเวียน, ตรงไป, ถึงแล้ว — ไทย + อังกฤษ) · ทดสอบ parser ด้วยตัวอย่างข้อความจริงหลายแบบ
- บอร์ด: `src/ui/NavScreen` — ลูกศรใหญ่ (วาดด้วยโค้ดแบบหน้าปัด), ระยะ, ชื่อถนน, ETA/ระยะที่เหลือ · **แถบนำทางบนหน้าปัด** (บรรทัดบน) ทั้ง 3 แบบ
  · ภาพ preview ด้วย `tools/dash_preview` แบบเดิม
- บอร์ด: tool `navigate` (เปิดเมื่อมือถือเชื่อมอยู่ — ประกาศแบบ opt-in เหมือน `vehicle` เพราะงบ declarations ~15 KB):
  `go(to)` / `stop` / `status` ("อีกไกลไหม", "ถึงกี่โมง") / `where` ("ตอนนี้อยู่ไหน" → Geocoder บนมือถือ)
- แอป: ทำคำสั่ง `navigate` → เปิด Google Maps โหมดนำทาง (ต้องได้สิทธิ์ "แสดงทับแอปอื่น" เพื่อเปิดจากเบื้องหลัง — **ทดสอบบนมือถือผู้ใช้ก่อนเฟสนี้**)
- เสียงนำทาง: ให้ **Google Maps พูด** (ผ่านลำโพงมือถือ/รถ) เป็นค่าเริ่มต้น · ตัวเลือก "ให้บอร์ดเตือนก่อนเลี้ยว" ทีหลัง (ใช้ช่องประกาศเดิมของ agent แต่กินโทเคน + แทรกบทสนทนา)
- **ผ่านเมื่อ:** พูด "นำทางไปเซ็นทรัลเวิลด์" → Maps เริ่มนำทางภายใน 5 วิ · จอบอร์ดตรงกับ Maps ทุกจุดเลี้ยวในเส้นทางทดสอบ 10 กม. · ถามระยะที่เหลือได้

### เฟส 3 — สั่งมือถือด้วยเสียง (ขนาด: M)
- บอร์ด: tool `phone` (opt-in เมื่อเชื่อม): `call(who)`, `sms(who, text)` (**ยืนยันด้วยเสียงก่อนส่งเสมอ**), `media(play|pause|next|prev)`, `notifications(read)`,
  `find` (ให้มือถือดัง), `volume`, `torch`, `answer` / `hangup`, `battery`
- แอป: `PhoneActions` — รายชื่อ (READ_CONTACTS) หา "แม่", ACTION_CALL, SmsManager, MediaController (ผ่าน notification listener), Ringtone ดังสุด, CameraManager.setTorchMode,
  TelecomManager · ทุกคำสั่งตอบ `result` ให้ AI พูดผล · แอปมีหน้าเปิด/ปิดแต่ละความสามารถ
- **ผ่านเมื่อ:** แต่ละคำสั่งทำงานจากเสียงขณะจอมือถือดับ · SMS/โทรไม่เกิดถ้าผู้ใช้ไม่ยืนยัน

### เฟส 4 — BLE (ทางเลือก, ขนาด: L, เสี่ยงสูง)
- ทำเมื่อเฟส 1–3 นิ่งแล้ว และ**วัด RAM ภายใน**ระหว่าง Live + คำปลุกก่อน: ถ้าไม่ถึง ~50 KB ว่าง ให้เปิด BLE ได้เฉพาะเมื่อคำปลุก 1 คำ (`set wakeword`)
  และไม่ใช้ OBD BLE พร้อมกัน (หรือรวมเป็น NimBLE ตัวเดียว central+peripheral)
- บอร์ด: GATT service แบบ "UART" (RX/TX characteristic) ส่งบรรทัดเดียวกัน · แอป: BLE central + CompanionDeviceManager
- **ผ่านเมื่อ:** เหมือนเฟส 1 + วัดเสียงกระตุก (`voice_underruns` ใน `diag`) ไม่เพิ่ม

### ทีหลัง/ถ้าต้องการ
- เส้นทาง + ตำแหน่งวาดบนจอ (ไม่ใช่ภาพแผนที่): ต้องมี polyline เส้นทาง — Google Maps ไม่ให้ผ่านการแจ้งเตือน → ต้องใช้บริการคำนวณเส้นทางเอง
  (Google Directions = มีค่าใช้จ่าย/ต้องมี key, OpenRouteService = key ฟรีจำกัดจำนวน) — ตัดสินใจภายหลัง
- บันทึกทริป (GPX) ลงการ์ด SD, เตือนความเร็วเกิน (ต้องมีข้อมูลจำกัดความเร็ว), จุดจอดรถ ("จอดรถไว้ไหน")

## 5. ความเสี่ยงหลัก

| ความเสี่ยง | ผล | ทางแก้/ลด |
|---|---|---|
| RAM ภายในบอร์ด (39 KB ตอนคุย AI) | BLE เปิดไม่ได้ / Wi-Fi ต่อไม่ติด | Wi-Fi ก่อน (ใช้น้อย), วัด RAM ทุกเฟส (`mem`), BLE เฉพาะเมื่อปิดบางอย่าง |
| Google Maps เปลี่ยนรูปแบบการแจ้งเตือน | จอนำทางว่าง/ลูกศรผิด | parser ยืดหยุ่น + ข้อความดิบแสดงแทนถ้าแยกไม่ได้ · test ด้วยตัวอย่างจริง |
| Android จำกัดงานเบื้องหลัง (แต่ละยี่ห้อ เช่น ColorOS/realme ปิดแอปเบื้องหลังแรง) | ลิงก์หลุดตอนจอดับ | foreground service + แนะนำปิด "ประหยัดแบตเตอรี่" ให้แอป · ทดสอบบนมือถือผู้ใช้ |
| เปิด Maps จากเบื้องหลังไม่ได้ | คำสั่ง "นำทางไป" ไม่ทำงาน | สิทธิ์ "แสดงทับแอปอื่น" / Companion Device / สำรอง: แจ้งเตือนให้แตะเปิด |
| Wi-Fi + BLE แชร์วิทยุ | เสียง AI กระตุก | BLE ท้ายสุด + วัด `voice_underruns` |
| ความปลอดภัย: คนอื่นใน Wi-Fi เดียวกันส่งคำสั่ง | สั่งโทร/ส่ง SMS แทน | จับคู่ + token, ชุดคำสั่งจำกัด, ยืนยันด้วยเสียงก่อนโทร/ส่ง SMS |
| สิทธิ์อ่อนไหว (ตำแหน่ง, รายชื่อ, SMS, แจ้งเตือน) | ผู้ใช้ไม่สบายใจ | ขอเฉพาะตอนเปิดใช้ความสามารถนั้น + อธิบายเป็นภาษาไทย · ข้อมูลไม่ออกนอกมือถือ/บอร์ด |

## 6. สิ่งที่ต้องตัดสินใจก่อนเริ่ม (ผู้ใช้ตอบแล้ว — ดูด้านบน)
1. ช่องทางแรก: **Wi-Fi (แนะนำ)** + USB ที่มีอยู่ — BLE เลื่อนไปเฟส 4 ได้ไหม
2. เส้นทาง: ใช้ **Google Maps บนมือถือ** (ฟรี, แนะนำ) หรืออยากได้เส้นทางวาดบนจอบอร์ด (ต้องมีบริการคำนวณเส้นทาง/API key)
3. เสียงนำทาง: Google Maps พูด (แนะนำ) หรือให้บอร์ด/AI พูด
4. ความสามารถสั่งมือถือที่ต้องการจริง (โทร, SMS, เพลง, อ่านแจ้งเตือน, หามือถือ, …) — ทำเฉพาะที่ใช้
5. รุ่น/ยี่ห้อมือถือที่ใช้ในรถ (น่าจะ Android 15 — อาการล้นจอใน T082 เกิดเฉพาะ Android 15) — ใช้ทดสอบทุกเฟส

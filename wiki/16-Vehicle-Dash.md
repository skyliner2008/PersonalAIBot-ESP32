# 16 — หน้าปัดรถ (รถยนต์ + มอเตอร์ไซค์)

> **Related:** [[00-Home-Dashboard]] · [[15-Expansion-Ports]] · [[09-Assistant-Profiles-and-Tools]] · [[07-Troubleshooting-Log#T076 หน้าปัดรถ — ฟีเจอร์ใหม่ เขียนเองทั้งหมด (MIT) จากแนวคิดของ redline-gauge]] · [[07-Troubleshooting-Log#T112]]
> โค้ด: `src/vehicle/` (ข้อมูล, โมเดลหน้าปัด, ตัวจำลอง, ELM327, **Obd** (PID/รหัสปัญหา/VIN), **VehicleHealth** (วิเคราะห์ + ทริป), Honda K-Line, task + UART/BLE) · `src/ui/DashScreen.*` · `tools/dash_preview/`

หน้าจอหน้าปัดแบบรถแข่ง: **บาร์รอบเครื่อง + shift light**, ความเร็วตัวใหญ่, เกียร์, และช่องอุณหภูมิเครื่อง / แบตเตอรี่ / อากาศเข้า (หรือคันเร่ง)
ค่าเตือนเปลี่ยนสี (เหลือง = สูง, แดงกระพริบ = วิกฤต, ฟ้า = เครื่องยังไม่ร้อน) · ค่าไหนไม่อัปเดตตามเวลาของมัน ขึ้น `--` (ไม่ค้างค่าเก่า)
และ AI รู้ค่าจริง: ถาม "รอบเครื่องเท่าไหร่" / "เครื่องร้อนไหม" ได้ · เครื่องร้อนจัดหรือไดชาร์จไม่ชาร์จ **AI พูดเตือนเอง**

**T112 — ระบบอัจฉริยะ:** OBD-II หา**โปรโตคอลเอง** (จำตัวที่ใช้ได้, ลองทีละโปรโตคอลเมื่อ auto หาไม่เจอ) + **baud ของ ELM327 เอง** ·
อ่าน **ทุก PID ที่รถมี** (0100→01C0) ด้วย**ลำดับความสำคัญตามที่จอ/AI ใช้** · **รหัสปัญหา** (stored / pending / permanent) **พร้อมความหมาย** + freeze frame
+ VIN + readiness + ไฟเช็คเครื่อง · **วิเคราะห์สุขภาพรถ** (ความร้อนขึ้นเร็ว, ไดชาร์จ, แบตตอนจอด/ตอนสตาร์ท, fuel trim บาง/หนา/รั่วอากาศ, เดินเบาไม่นิ่ง,
น้ำมันใกล้หมด) · **ทริป + กม./ลิตร** (จาก PID 5E / MAF / MAP) · ความเร็วจาก **GPS มือถือ** เมื่อรถไม่มี · หน้าจอแบบที่ 4 **"ข้อมูลรถ + วิเคราะห์"** ·
AI: `vehicle` `status` / `scan` / `explain` / `clear_codes` — ดู [ระบบอัจฉริยะ (T112)](#ระบบอัจฉริยะ-t112)

## รูปแบบหน้าปัด 4 แบบ (T077, T112)

ค่าและคำเตือนเหมือนกันทุกแบบ เปลี่ยนได้ทันที: **แตะข้อความสถานะบนแถบหัว** (วนไปแบบถัดไป + ป้ายบอกชื่อ 1.5 วิ) · เมนู "หน้าปัดรถ → รูปแบบหน้าปัด" ·
console `dash style <race|digital|classic|info>` · จำใน NVS `veh/style` · วาดด้วยโค้ดล้วน (ไม่มีรูปภาพ: flash +6 KB)
· ไฟเช็คเครื่องติด / มีรหัสปัญหา = **รูปเครื่องยนต์สีเหลืองอำพัน + จำนวนรหัส** บนแถบหัวทุกแบบ (T112)

| แบบ | หน้าตา |
|---|---|
| **รถแข่ง** (`race`, ค่าเริ่มต้น) | บาร์รอบเครื่องเต็มความกว้างด้านบน, รอบ/ความเร็ว/เกียร์ตัวใหญ่, 3 ช่องด้านล่าง |
| **วงกลมดิจิทัล สปอร์ต** (`digital`) | วงแหวนไฟ 34 ช่อง 270° (ช่องที่ติดยื่นออกมา, เขียว/เหลือง/แดง, กะพริบขาวเมื่อถึง shift), รอบ + ความเร็วดิจิทัลกลางวง, เกียร์ในช่องว่างใต้วง, 3 ช่องด้านขวา |
| **เข็มวงกลม คลาสสิก** (`classic`) | หน้าปัดวัดรอบ (โซนแดงเริ่มที่รอบ shift, ช่องเกียร์) + หน้าปัดความเร็ว (0–200 รถยนต์ / 0–140 มอเตอร์ไซค์ + ตัวเลขดิจิทัล), เข็มเรียวลบรอยหยัก + เข็มความเร็วเลื่อนนุ่ม, ไฟ **SHIFT** ระหว่างหน้าปัด, 3 ช่องด้านล่าง · ขีด/ตัวเลขวาดครั้งเดียวลง sprite ใน PSRAM (150 KB) แล้วคัดลอกทุกเฟรม |
| **ข้อมูลรถ + วิเคราะห์** (`info`, T112) | **9 ช่อง**: ความเร็ว รอบ เครื่องยนต์ แบต เสมอ + ค่าที่รถคันนี้มี (ชดเชยน้ำมัน B1, ภาระเครื่อง, น้ำมันในถัง, กม./ลิตร หรือ ลิตร/ชม., อากาศเข้า, ท่อไอดี, MAF, คันเร่ง, องศาไฟ, น้ำมันเครื่อง, อากาศภายนอก, ระยะทริป) · แถบล่าง: **รหัสปัญหา** (แดง = ร้ายแรง, เหลือง = ควรตรวจ, "รอยืนยัน" = pending) หรือ "ไม่พบรหัสปัญหา • ระบบพร้อม 5/6" + **สิ่งผิดปกติที่ร้ายแรงสุด** · **แตะแถบล่าง = อ่านรหัสใหม่** · **กดค้าง = เริ่มทริปใหม่** · เปิดหน้านี้ = OBD อ่านค่าละเอียดเร็วขึ้น (ดู "ดึงค่าตามที่จอใช้") |

### Bluetooth: เฟิร์มแวร์แยก `esp32s3-ble` — ใช้พร้อมผู้ช่วยเสียงได้แล้ว (T078 → T113)
เฟิร์มแวร์ปกติ (`pio run`, OTA, release) **ไม่มี** แหล่ง `obd_ble` (เมนูซ่อน, `dash source obd_ble` ตอบ error, ค่าเก่าใน NVS ปิดตอนบูต)
· ใช้ BLE: **`pio run -e esp32s3-ble -t upload --upload-port COM3`** แล้ว `dash source obd_ble` (หรือเมนู) + รีสตาร์ท 1 ครั้ง
· **อัปเดต OTA จะได้เฟิร์มแวร์ปกติ (ไม่มี BLE) — แหล่ง `obd_ble` จะถูกปิด** ต้องแฟลช `esp32s3-ble` ใหม่ทางสาย

**T078 (เดิม):** แค่ลิงก์ BLE ก็เพิ่ม `.iram0.text` ~22 KB (บน S3 คือ SRAM ก้อนเดียวกับ heap ภายใน) → heap ระหว่าง session 19 KB และ TLS ของ Gemini ล้ม
`esp-aes: Failed to allocate memory` · **T113:** หา RAM ภายในคืนจนใช้ BLE + Live session + web tools พร้อมกันได้ (วัดบนบอร์ด, adapter `OBDII` ของผู้ใช้):

| เฟิร์มแวร์ / สถานะ | RAM ภายในระหว่าง session: ว่าง / ต่ำสุด / ก้อนใหญ่สุด |
|---|---|
| ปกติ ก่อน T113 | 32 / 27 / 19 KB |
| ปกติ หลัง T113 | **69 / 62 / 30 KB** |
| `esp32s3-ble` ก่อน T113, BLE ไม่ได้เปิด | 11 / 8 / 7 KB — TLS ล้ม |
| `esp32s3-ble` ก่อนเพิ่มการประหยัดเฉพาะ BLE, **BLE เปิด** + ต่อ adapter | 5 / 0 / 2 KB — TLS ล้ม |
| `esp32s3-ble` หลัง T113, BLE ไม่ได้เปิด | 49 / 42 / 30 KB |
| `esp32s3-ble` หลัง T113, **BLE เปิด + ต่อ adapter** + ดึงอากาศ / ข่าว / ราคาทอง | **33–35 / 20 / 22 KB** — ใช้ได้ |

ที่ทำ (รายละเอียด [[07-Troubleshooting-Log#T113]]): ของในโปรเจคที่อยู่ใน RAM ภายในย้ายไป PSRAM (`gCard` 7 KB, buffer เสียง 13 KB, buffer ไมค์ 5 KB,
ตารางคีย์บอร์ด) · task OTA มีเฉพาะตอนเช็ก/ติดตั้ง (stack 10 KB) · stack `audioIn` 6 → 3 KB, `ui` 8 → 6 KB · **เฉพาะ build BLE:** pool ของ NimBLE host → PSRAM
(`-Wl,--wrap=nimble_mem_*`), BT controller รับ activity 3 (เดิม 6) + รายการกันซ้ำ 20 (เดิม 100) (`--wrap=esp_bt_controller_init`), task รถใช้ stack PSRAM
(`BLEDevice::init` ที่อ่าน NVS รันบน task ชั่วคราว) · **เฉพาะตอนแหล่งเป็น `obd_ble`:** ฟังคำปลุก "Jarvis" คำเดียว (2 คำ = +16 KB) และ mbedTLS จองใน PSRAM ทั้งหมด
(handshake ของ web tool เคยดึง RAM ลงเหลือ 4 KB)

### Bluetooth เปิด/ปิดตามหน้าปัด (T114)
แหล่ง `obd_ble`: **บลูทูธเปิดเมื่อเปิดหน้าปัด** (ต่อ adapter ที่จำไว้ ~3 วิ) และ **ปิดเมื่อหน้าปัดไม่อยู่บนจอ 15 วิ** (เผื่อเข้าหน้าตั้งค่าของหน้าปัด)
→ controller + NimBLE host หยุด (`BLEDevice::deinit(false)`) RAM ภายในคืนให้ผู้ช่วย · หน่วยความจำ BT ที่จองไว้ตอนบูตยังอยู่ จึงเปิดใหม่ได้ไม่ต้องรีบูต
· วัดบนบอร์ด (มี Live session): บลูทูธเปิด RAM ภายในว่าง **33–38 KB** → ปิด **76–78 KB** ทุกรอบ (เปิด/ปิดหลายรอบไม่รั่ว) · สถานะตอนปิด `BT OFF`
· ขณะปิด: ไม่มีค่าสด/การวิเคราะห์/คำเตือนจาก OBD · AI ถามสถานะรถได้ผล `note` ให้เรียก `vehicle open` ก่อน (เปิดหน้าปัดด้วยเสียงก็เปิดบลูทูธ)
· บั๊กที่เจอ: เวลาที่ UI บันทึก (`now | 1`) อาจเร็วกว่า `millis()` ของ task รถ 1 ms ลบแบบ unsigned = ค่ามหาศาล → บลูทูธปิด-เปิดเองถี่ๆ → เทียบแบบ signed
· `deinit` ลบ client ตัวล่าสุดที่ BLEDevice จำไว้ ซึ่ง `close()` ลบไปแล้ว → สร้าง client ใหม่ก่อน deinit กัน double free (`vehicleBleShutdown`)

### Bluetooth: บอร์ดนี้ (ESP32-S3) มีแค่ **Bluetooth LE**
ELM327 ราคาถูกส่วนใหญ่เป็น **Bluetooth Classic (SPP)** → **ต่อตรงไม่ได้** · ต้องเป็นรุ่น **BLE** เช่น Vgate iCar Pro BLE, Veepeak BLE, Konnwei BLE, OBDLink CX
หรือรุ่น **dual-mode** (มีทั้งสองแบบ) — ตัวที่ผู้ใช้มี: ชื่อ `OBDII`, Classic = `BC:9A:78:56:34:12`, **BLE = `00:10:CC:XX:XX:XX`** (บริการ FFF0: notify FFF1 / write FFF2) ✅ ต่อได้ (T113)
· เช็กง่ายๆ: แอปอย่าง Car Scanner เลือก "Bluetooth LE (4.0+)" แล้วสแกน — ถ้าเจอ adapter แปลว่าบอร์ดต่อได้
(สเปก "Bluetooth 4.2 BR/EDR + LE" เป็นของ ESP32 รุ่นแรก เช่นบอร์ด CYD — ไม่ใช่ ES3C28P: framework ระบุว่า S3 ไม่มี BR/EDR)
- **Bluetooth เริ่มไม่ได้ (`BT FAIL`, T113):** เดิม `BLEDevice::init` ล้มแล้วโค้ดยังสแกนต่อ → crash ทุกครั้งที่บูต (วนรีบูตเพราะแหล่งถูกบันทึกไว้) —
  ตอนนี้หยุดที่ `BT FAIL` จนรีบูตครั้งหน้า · ถ้าบอร์ดวนรีบูตด้วยเฟิร์มแวร์เก่า: แฟลชเฟิร์มแวร์ปกติ (ปิด `obd_ble` เองตอนบูต)
- **รีสตาร์ท 1 ครั้งหลังเลือก `obd_ble`**: Arduino คืนหน่วยความจำของ BLE (~36 KB RAM ภายใน) ตอนบูตถ้าไม่มีใครใช้ — `bleInUse()` (`VehicleLink.cpp`)
  อ่าน NVS ตอนบูตแล้วเก็บไว้เฉพาะเมื่อแหล่งข้อมูลเป็น `obd_ble` · แหล่งอื่น/ไม่ใช้หน้าปัด = RAM เท่าเดิม
- ค้นหา 6 วิ เลือกตัวที่ชื่อ/บริการดูเป็น OBD (`OBD`, `ELM`, `VLINK`, `VEEPEAK`, `KONNWEI`, `VGATE`, บริการ FFF0/FFE0/18F0) ที่สัญญาณแรงสุด → จำ address ไว้ต่อตรงครั้งหน้า
  (เมนู "ค้นหา adapter Bluetooth ใหม่" / `dash ble forget` ล้างที่จำ) · log `[Vehicle]   AA:BB:..  ชื่อ  rssi  <- OBD?` แสดงทุกตัวที่เจอ
- ช่องข้อมูล: คู่ที่รู้จัก (FFF0: FFF1/FFF2, FFE0: FFE1, 18F0: 2AF0/2AF1, Nordic UART, E7810A71) ไม่งั้นใช้ notify + write คู่แรกที่เจอ
- RAM ภายในเหลือ < 40 KB ตอนจะเปิด Bluetooth → ไม่เปิด (สถานะ `BT NO RAM`) — Bluetooth เริ่มตอนบูต (ก่อน session ของ Gemini) จึงปกติไม่เจอ
- หา adapter ไม่เจอ (ดับเครื่อง/ถอดออก) → สแกนใหม่ทุก 15 วิ: การสแกน BLE ใช้คลื่นร่วมกับ Wi-Fi (เสียง AI อาจสะดุดช่วงสแกน) — T116: สแกนแค่ 30 ms ทุก 100 ms (เดิม 99 ms) ให้ Wi-Fi ได้เวลา 70%

### Honda K-Line (มอเตอร์ไซค์หัวฉีด PGM-FI: Wave 110i / 125i, Click, PCX, MSX ...)
- สาย K-Line ไฟ 12V → **ต้องมีบอร์ดแปลง** (L9637D / MC33290 / โมดูล "K-Line to TTL") — **ห้ามต่อ K-Line เข้าขาบอร์ดตรงๆ**
- ต่อ: K ↔ K-Line ของปลั๊กวิเคราะห์ (DLC), VS ↔ 12V รถ, GND ↔ GND รถ + GND บอร์ด, **TX ของบอร์ด (GPIO 43) → TX/IN ของโมดูล**, **RX/OUT ของโมดูล → GPIO 44**
  · ขา GPIO รับได้ **3.3V เท่านั้น**: โมดูลที่ดึง RX ขึ้น 5V ต้องลดระดับ (หรือใช้รุ่น 3.3V) · เฟิร์มแวร์เปิด pull-up ภายในที่ GPIO 44 ให้ (L9637D เป็น open collector)
  · ขาช่อง UART บนบอร์ด **สันนิษฐาน** ว่าเป็น GPIO 43/44 (wiki 15) — วัดยืนยันก่อน · ตอนบูต ROM พิมพ์ข้อความออก TX: ECU ไม่สนใจเพราะยังไม่ได้ปลุก
- โปรโตคอล: 10400 baud · ปลุก K-Line low 70 ms / high 130 ms → `FE 04 FF FF` → `72 05 00 F0 99` (ตอบ `02 04 00 FA`) → ขอตาราง `72 05 71 <table> <cs>` ~15 ครั้ง/วิ
  · checksum = ผลรวมทุกไบต์ของเฟรม = 0 (mod 256) · ตัดเสียงสะท้อน (echo) ที่โมดูลส่งกลับให้เอง
- **ตำแหน่งข้อมูลในตาราง (layout) แต่ละรุ่นไม่เหมือนกัน** — ค่าเริ่มต้น: ตาราง 0x11, รอบ = ไบต์ 0–1, อุณหภูมิ 5, อากาศเข้า 7, MAP 9, แบต 12 (÷10), ความเร็ว 13
  **ยังไม่ได้ทดสอบกับรถจริง**: ดูไบต์ดิบด้วย `dash kdump` แล้วแก้ใน `agent/vehicle.json`:
  `{"kline": {"table": 17, "rpm": 0, "coolant": 5, "intake": 7, "map": 9, "battery": 12, "speed": 13, "throttle": -1}}` (-1 = ไม่อ่าน)
- Wave รุ่นเรือนไมล์สายกล ECU ไม่รู้ความเร็ว → ความเร็วเป็น `--` · มอเตอร์ไซค์ไม่แสดงเกียร์ (ค่าเริ่มต้นไม่ประมาณ)

### OBD-II ผ่าน ELM327 (BLE หรือสาย) — T112
1. **เชื่อม:** `ATZ` → `ATE0` `ATL0` `ATS0` `ATH0` `ATAT1` → `ATSP0` (หรือ **`ATSPA<p>`** = auto แต่ลองโปรโตคอลที่ใช้ได้ครั้งก่อนก่อน, จำใน NVS `veh/proto`)
   → `0100` (SEARCHING... หารถ) · auto หาไม่เจอ 2 ครั้ง → **ลองทีละโปรโตคอล** `ATSP6 8 7 9 5 4 3 1 2` (CAN ก่อน: รถไทยส่วนใหญ่หลังปี 2008) แล้ววนกลับ auto
   · adapter เงียบที่ baud นี้ (ATZ ไม่ตอบ 3 ครั้ง) → **ลอง baud ถัดไป** แล้วจำตัวที่ตอบ (`veh/elmbaud`) — บันทึกจาก task ของ agent (`Vehicle::service`) เพราะ task รถใช้ stack PSRAM
2. **รถมีอะไร:** `ATDPN` (โปรโตคอล) + `0120` `0140` … `01C0` ต่อกันเท่าที่ช่วงก่อนหน้าบอกว่ามี (หลาย ECU ตอบ = รวม bitmap) → `0151` ชนิดเชื้อเพลิง, `0902` **VIN**
3. **รหัสปัญหา:** `0101` (ไฟเช็คเครื่อง + จำนวนรหัส + readiness) → `03` stored · `07` pending · `0A` permanent → `020200` (รหัสที่เก็บ freeze frame)
   → `020C00` `020D00` `020500` … (ค่าตอนเกิดปัญหา) · ทำตอนเชื่อมต่อ, ทุก 5 นาที, **เมื่อ 0101 บอกว่าจำนวนรหัส/ไฟเปลี่ยน**, และเมื่อสั่ง (AI / เมนู / แตะแถบล่าง)
   · ผลทั้งชุดเผยแพร่พร้อมกันตอนจบ (`scanSeq` +1) · ขั้นที่รถเก่าไม่ตอบ (VIN, 0A) ข้ามไป ไม่รีเซ็ต adapter
   · รองรับ CAN แบบหลายเฟรม (`014` / `0:` `1:` …) และ ISO 9141 / KWP / J1850 (VIN 5 บรรทัด, รหัส 3 ตัวต่อบรรทัด) · ตัวเลขรหัส → ความหมายจากตาราง SAE J2012 ในเฟิร์มแวร์ (`Obd.cpp`)
4. **ล้างรหัส:** `04` → อ่านใหม่ · **ต้องดับเครื่อง เปิดสวิตช์** (เฟิร์มแวร์ไม่ส่งถ้ารอบ > 400) · ECU ปฏิเสธ (`7F 04 22`) = แจ้งว่าปฏิเสธ
5. **ดึงค่าตามที่จอใช้ (smart polling):** แต่ละ PID มีความถี่ที่ต้องการ 2 ชุด (`obd::Pid`: ตอนจอแสดง / ตอนปิดจอ) → ถาม **ตัวที่เลยกำหนดมากที่สุด** ก่อน
   · มีหน้าปัดเปิดอยู่ = รอบเครื่องทุกคำสั่งเว้นคำสั่ง (ช่องที่เหลือ: งานสแกน แล้วค่าอื่น) · หน้า `info` = ทุกค่าเร็วเท่ากัน · **ปิดจอ** = เฉพาะที่ถึงเวลา (การวิเคราะห์/AI ยังได้ค่า; ทดสอบ: 1000 → 48 คำสั่ง/10 วิ)
   · ค่าสดอยู่ได้ **3 เท่าของเวลาจริงระหว่างสองครั้งที่อ่าน** (ต่ำสุด 2.5 วิ) — บัสช้า (ISO 9141 ~5 คำสั่ง/วิ) ค่าช้าลงแทนขึ้น "--"
   · `ATRV` ทุก 2 วิ, **ทุก 0.5 วิตอนเปิดสวิตช์แต่เครื่องไม่ติด** (จับแรงดันตกตอนสตาร์ท), adapter วัดไม่ได้ → ใช้ PID 42 แทน
6. **ผิดพลาด / หลุด:** ไม่ตอบ 3 ครั้ง = เริ่มใหม่ (`NO ADAPTER`) · PID ที่ตอบ `NO DATA` 3 ครั้ง = เลิกถาม (จนเชื่อมต่อใหม่) · ตอบว่างติดกัน ≥ 8 ครั้ง + ไม่มีข้อมูล 5 วิ
   หรือ `UNABLE TO CONNECT` / `BUS ERROR` = `NO ECU` (ดับเครื่อง) → ลองใหม่ทุก 4 วิ (หลัง 1 นาที ทุก 15 วิ) และ **อ่านแบตตอนจอดทุก 10 วิ**
· รถยนต์เกือบทุกคันที่ขายในไทยหลังปี 2008 มี OBD-II · มอเตอร์ไซค์ส่วนใหญ่ **ไม่มี** OBD-II มาตรฐาน → ใช้ K-Line · J1939 (รถบรรทุก) ไม่รองรับ

## เกียร์ / ค่าเตือน
- เกียร์: ใช้ค่าจากแหล่งข้อมูลถ้ามี (`gear=` ใน serial) ไม่งั้น **ประมาณจากรอบ ÷ ความเร็ว** เทียบอัตราทดเกียร์ (ค่าเริ่มต้นรถเก๋ง 5 เกียร์ 1.5 ลิตร, ล้อ 195/65R15)
  ไม่ตรงเกียร์ไหน (คลัตช์ลื่น/ปลดเกียร์) = `-` · จอดนิ่งรอบเดินเบา = `N` · มอเตอร์ไซค์ปิดไว้
- เตือน (รถยนต์ / มอเตอร์ไซค์): อุณหภูมิเครื่อง ≥ 105/120°C เหลือง, ≥ 112/135°C แดง · < 60/50°C ฟ้า · แบต < 11.8/12.0 V ขณะเครื่องติด หรือ > 15.2/15.0 V
- AI พูดเตือนเมื่อเครื่องร้อนวิกฤต / ไดชาร์จไม่ชาร์จ / ไฟชาร์จสูงเกิน (T112: จากการวิเคราะห์สุขภาพรถ ดูด้านล่าง) — ข้อมูลจำลองบอกว่า "(ข้อมูลจำลอง)"

## Log OBD ลง SD card + เล่นย้อนหลัง (T115)

> ใช้กับรถไปพร้อมกับให้ Claude ดูไม่ได้ → บอร์ด**บันทึกทุกอย่างของแหล่ง OBD ลง SD card** แล้วนำไฟล์กลับมาให้ตรวจ แก้ และ**เล่นย้อนหลังเป็นแบบจำลอง**
> โค้ด: `src/vehicle/ObdLog.*` (รูปแบบ + ตัวเล่นย้อนหลัง, host tested) · `src/vehicle/VehicleLog.*` (ตัวเขียนลง SD) · `ReplayLink` (`VehicleLink.h`) · `tools/obd_log.py`

**บันทึกอะไร** — ไฟล์ข้อความ `agent/obdlog/20261027-171713-obd_ble.log` (บนการ์ด) หนึ่งบรรทัดต่อ record: `<ms นับจากเริ่มไฟล์> TAB <ชนิด> TAB <ข้อความ>`

| ชนิด | เนื้อหา | ตัวอย่าง |
|---|---|---|
| `>` / `<` / `!` | ทุกคำสั่งที่ส่งไป ELM327 / คำตอบทั้งก้อน (บรรทัดคั่นด้วย `\|`) / ไม่ตอบในเวลา | `5436  >  0100` · `11312  <  SEARCHING...\|UNABLE TO CONNECT\|` |
| `S` | สถานะเมื่อเปลี่ยน | `NO ECU`, `LIVE`, `BT CONNECT` |
| `E` | เหตุการณ์: แหล่ง/เฟิร์มแวร์/RAM ตอนเริ่ม, บลูทูธเปิด-ปิด, ผลสแกน BLE, ต่อ adapter, เปลี่ยน baud, ล้างรหัส, โน้ตจาก console | `BLE: 00:10:cc:xx:xx:xx connected (notify ...fff1, write ...fff2)` |
| `D` | ค่าที่ถอดรหัสแล้ว ทุก 1 วิ | `rpm=812 speed_kmh=0 coolant_c=57 battery_v=13.40` |
| `C` / `H` | การวินิจฉัย (ไฟเช็คเครื่อง รหัส readiness VIN โปรโตคอล) / สุขภาพรถ — เมื่อเปลี่ยน | `mil=1 stored=P0420 pending=P0171 ready=5/6 proto=6 vin=...` |
| `F` / `L` | ตาราง Honda K-Line (hex) / บรรทัดจากแหล่งข้อความ | |

**เมื่อไหร่** — แหล่งจริงเท่านั้น (`obd_ble`, `obd_uart`, `kline`, `serial` — ไม่ใช่ตัวจำลอง/GPS/ตัวเล่นย้อนหลัง):
`obd_ble` = 1 ไฟล์ต่อการเปิดหน้าปัด (บลูทูธเปิด → ปิด) · `obd_uart` = ตั้งแต่เริ่ม ปิดไฟล์เมื่อไม่มี ECU 10 นาที เปิดใหม่เมื่อรถตอบ · ไฟล์ใหม่ทุก 2 MB ·
เก็บได้ 200 ไฟล์ / 256 MB (ลบเก่าสุดก่อน) · ~1–2 KB/วินาทีตอนรถติด (≈ 4–7 MB/ชั่วโมง)
**ทนไฟดับ** — เขียนผ่าน buffer ใน PSRAM 2 × 32 KB โดย task แยก (ไม่บล็อกการอ่าน OBD) + `fsync` ทุก 2 วิ: ดับรถแล้วไฟบอร์ดตัด เสียไม่เกิน ~2 วิสุดท้าย
· SD card เท่านั้น (ไม่มีการ์ด = ปิด — flash ภายใน 2.6 MB จะเต็มและสึก) · เปิด/ปิด: เมนูหน้าปัดรถ → "บันทึก log OBD ลง SD" / `obdlog on|off` (NVS `veh/log`, ค่าเริ่มต้นเปิด)

**นำกลับมาให้ตรวจ**
1. ถอด SD card ไปเสียบ PC → copy `agent/obdlog/*.log` หรือ
2. ต่อบอร์ดกับ PC ด้วยสาย USB:
   ```
   python tools/obd_log.py list --port COM3
   python tools/obd_log.py pull latest --port COM3        (หรือ all / ชื่อไฟล์) -> logs/obd/   (ตรวจ sha256, ส่วนที่หายขอซ้ำเอง)
   python tools/obd_log.py summary logs/obd/<ไฟล์>.log      (คำสั่ง: จำนวน/เวลาตอบเฉลี่ย-สูงสุด/timeout/NO DATA, error ของ adapter, ไทม์ไลน์, สรุปค่า)
   python tools/obd_log.py csv logs/obd/<ไฟล์>.log          (ค่า D เป็น CSV ทำกราฟ)
   python tools/obd_log.py replay logs/obd/<ไฟล์>.log       (เล่นผ่านตัวคุยกับ ELM327 ของเฟิร์มแวร์บน PC = host_tests --replay)
   ```
   (`logs/` อยู่ใน `.gitignore`: มี VIN / เส้นทางการขับของผู้ใช้)
· console: `obdlog` (สถานะ + รายชื่อไฟล์), `obdlog get <ไฟล์> [offset] [len]` (base64 + sha256 ที่เครื่องมือใช้), `obdlog rm <ไฟล์|all>`,
  **`obdlog note <ข้อความ>`** — ทำเครื่องหมายในไฟล์ระหว่างขับ เช่น "เดินเบาสั่นตอนนี้"

**เล่นย้อนหลัง (แบบจำลองจากการขับจริง)** — แหล่งข้อมูลใหม่ `replay` ("เล่นย้อนหลังจาก log"):
เมนูหน้าปัดรถ → "เล่นย้อนหลังจาก log" → เลือกไฟล์ · `dash replay [ไฟล์|latest] [ความเร็ว]` · AI `vehicle set_source replay` (ไฟล์ล่าสุด)
- log ที่มีการคุยกับ adapter: **`ReplayAdapter` เป็น ELM327 จากการบันทึก** — ตอบแต่ละคำสั่งด้วยคำตอบของคำสั่งเดียวกัน ณ เวลานั้นของการขับ
  หน่วงเท่าของจริง (คำสั่งที่ไม่เคยบันทึก: AT → `OK`, อื่น → `NO DATA`; ครั้งที่ไม่ตอบ → เงียบเหมือนเดิม) → **ตัวคุยกับ ELM327 ตัวเดียวกับของจริง**
  จึงได้โปรโตคอล รหัส VIN freeze frame ค่าสด การวิเคราะห์ และ AI ครบ — และ**เวอร์ชันที่แก้แล้วเจอรถคันเดิมอีกครั้ง**บน PC ได้ (`host_tests --replay`)
- log ที่ไม่มี (K-Line, ข้อความ): เล่นค่า `D` ตามเวลา · เริ่มที่คำสั่งแรก จบแล้ววนใหม่ · ไม่เขียน log ซ้ำ ไม่เรียนรู้โปรโตคอลจาก replay ·
  AI ได้ `replay {file, at_s, length_s}` + note "ข้อมูลย้อนหลัง ไม่ใช่รถตอนนี้" · คำเตือนต่อท้าย "(ข้อมูลย้อนหลังจาก log ...)" · ไม่ประกาศรหัสใหม่

**ทดสอบ (2026-10-27):** host tests (บันทึกรถจำลอง 20 วิ → เล่นย้อนหลัง → โปรโตคอล/รหัส/VIN/รอบเครื่องแต่ละช่วงตรง, escape, timeout, วนรอบ) ·

## AI tool `vehicle`
ประกาศ **ทุก session** (T079) · T112: 582 bytes (เดิม ~380), รวมทั้งชุด < 16,300 bytes (host test) · คำอธิบาย "Car/motorbike dash (หน้าปัด, Smart Gauge, OBD-II)"
- `action`: `status` (ค่าสด + สุขภาพ + ทริป + รหัสปัญหา), **`scan`** (อ่านรหัสจากรถตอนนี้ + freeze frame, readiness, VIN, โปรโตคอล), **`explain`** + `code`
  (ความหมายของรหัส เช่น `"P0171, P0302"` — **ไม่ต้องมีรถ** ตอบจากตารางในเฟิร์มแวร์: meaning, system, severity 1–3, generic), **`clear_codes`** (เฉพาะเมื่อผู้ใช้สั่ง;
  รถจริงต้องดับเครื่อง), `open` / `close` (หน้าปัด; `open` ตอนแหล่งเป็น `off` = เริ่มตัวจำลอง + `note`), `set_source` + `source`
- **`scan` / `clear_codes` ตอบทีหลังเหมือน web tool:** `AgentController::deferVehicleCall` ขอให้ task รถอ่าน → `handleVehicle` รอ `scanDone` (≤ 15 วิ) → ใส่ใน `_toolBatch`
  ส่งรวมกับผลของ web tool (`_webPending`) · ตัวจำลองใช้เวลา 1.2 วิ · แหล่งที่ไม่มีรหัส / ไม่ได้ต่อ ECU = ตอบทันทีพร้อม `note`
- ผล: `readings` (เฉพาะที่สด ทศนิยมตามความละเอียดของค่า: `rpm`, `speed_kmh`, `coolant_c`, `battery_v`, `load_pct`, `stft_b1_pct`, `ltft_b1_pct`, `maf_gs`,
  `fuel_pct`, `ambient_c`, `km_since_clear` …) · `health` {`overall`, `findings` [{what, level, value}], `coolant_change_c_per_min`, `fuel_trim_b1_avg_pct`,
  `battery_engine_off_v`, `battery_charge_pct_approx`, `last_start_lowest_v`} · `trip` {km, engine_min, idle_min, avg_kmh, max_kmh, fuel_l, km_per_l, km_per_l_now,
  fuel_lph_now, fuel_from} · `diagnosis` {check_engine_light, codes [{code, status, meaning, severity}], read_s_ago, last_clear; `scan` เพิ่ม readiness,
  freeze_frame, vin, protocol, supported_pids} · จำลอง = `simulated: true`
- ทดสอบด้วยเสียงโดยไม่มีรถ: "เปิดหน้าปัด" (ตัวจำลอง) → "สแกนรถให้หน่อย" (P0420 + P0171 รอยืนยัน, ไฟเช็คเครื่องติด) → "P0420 คืออะไร" → "ล้างรหัสปัญหา" → "รถเป็นยังไงบ้าง"

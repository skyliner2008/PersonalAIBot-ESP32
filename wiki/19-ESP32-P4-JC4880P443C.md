# 🧩 ESP32-P4 firmware — Guition JC4880P443C_I_W (`firmware-p4/`)

ผู้ใช้ (2026-10-29): "ไม่จำเป็นต้องทำร่วมกับตัว ESP32-S3 ... ทำ FIRMWARE แยกออกมาได้เลย เพราะบอร์ด ESP32-S3 กับ ESP32-P4 ต่างกันเยอะ
ต้องการให้ความสามารถพื้นฐานของบอร์ด ESP32-P4 คล้ายกับ ESP32-S3" + "ตรวจสอบและเพิ่มเติมให้เป็น AI Assistant ที่ ... ดึงความสามารถของบอร์ดมาใช้ได้อย่างมีประสิทธิภาพสูงสุด"

## โครงสร้าง

- `firmware-p4/` = โปรเจค PlatformIO ของตัวเอง: `platformio.ini`, `partitions_p4.csv`, `include/pins_config.h` (ขาของบอร์ดนี้อย่างเดียว), `src/` (สำเนาจาก `../src`
  แล้วแก้อิสระ — ไม่มี `#if` ของ S3) · ใช้ร่วมกับ repo: `../lib` (Helix MP3/AAC), `../models/srmodels.bin` ("Jarvis" + "Hi ESP" — ชุดของ SDK P4 มีแค่ Hi ESP),
  `../tools/pio_*.py`, wiki, ESP32-AI Studio
- เฟิร์มแวร์ S3 (`../src`, `pio run`) **ไม่มีโค้ด P4 เลย** — งาน P4 ที่เคยใส่รวมไว้ (`#if BOARD_JC4880P443C`) ย้ายมาที่นี่ทั้งหมด
- Build: `pio run -d firmware-p4` (ค่าเริ่มต้น `esp32p4-r3` = rev 3.x, T147) · `pio run -d firmware-p4 -e esp32p4` (ชิปก่อน rev 3.0) · แฟลช: `pio run -d firmware-p4 -t upload`
  ผ่าน **USB Serial/JTAG ของ P4** (พอร์ตเดียวกับ console / ESP32-AI Studio — บนบอร์ดมี CH340 อีกพอร์ต ซึ่งไม่ใช่ console)
  · ใช้ secrets ของตัวเอง: `firmware-p4/include/secrets.h` (git-ignore, คัดลอกจาก `secrets.example.h`)
- **เลือก env ตามรุ่นชิป** (`esptool chip_id` บอก revision): image ของอีกรุ่นบูตไม่ขึ้น — **บอร์ดของผู้ใช้เป็น ESP32-P4 v3.2** (= `esp32p4-r3`, T147)
  ส่วนบอร์ดที่อีกโปรเจคตรวจเป็น v1.3 (= `esp32p4`)
- **ชิป C6 ต้องมี ESP-Hosted รุ่นเดียวกับฝั่ง P4** (T147): บอร์ดมาจากโรงงานด้วย 2.3.2 = **ไม่มี Wi-Fi** · console `hosted` บอกเวอร์ชันทั้งสองฝั่ง
  · อัปเดตผ่าน USB เส้นเดิม: `python tools/p4_c6_update.py COM5` (บอก URL ไฟล์ที่ตรงรุ่นจาก espressif.github.io/arduino-esp32/hosted/)
  → `python tools/p4_c6_update.py COM5 esp32c6-v2.12.13.bin` (~2.5 นาที, ล้มกลางทาง C6 ยังใช้รุ่นเดิม) · ต้องทำซ้ำเมื่อขึ้น Arduino-ESP32 รุ่นใหม่

## ขาต่อขยาย (`util/DeviceConfig.h`, devices.json)

ใช้ได้ (ตามขา JP1 จริง, T132): **28–34, 49–52** · analog: **49–52** (ADC2 — P4 ไม่มีวิทยุ Wi-Fi ในตัวจึงไม่ชน) · 26/27 = UART J5 + RS485 ·
**ห้าม 14–19 / 54** (SDIO ของ C6: ใช้แล้ว Wi-Fi หลุด) · 48 = I2S DIN (ไมค์) · 35 = ปุ่ม BOOT

## RS485 / Modbus RTU (T131)

- **เปิด** (ครั้งเดียว, เก็บใน `agent/rs485.json`): `rs485 set 9600` (หรือ `rs485 set 9600 8E1`) = MAX485 ของบอร์ด GPIO 26/27 ·
  `rs485 set <tx> <rx> <baud> [fmt] [de]` = transceiver อื่น · `rs485` = สถานะ · `rs485 off` · UART2 โหมด `RS485_HALF_DUPLEX` (ตามตัวอย่างผู้ผลิต)
  · ใช้ขาเดียวกับ UART J5: เปิด RS485 อยู่ = แหล่งหน้าปัดรถแบบสายถูกปฏิเสธ
- **ทดสอบจาก console:** `modbus read <slave> <holding|input|coil|discrete> <addr> [count]` · `modbus write <slave> <holding|coil> <addr> <value>`
- **AI:** tool `modbus` (declare เมื่อตั้งขาแล้ว) — read คืน `values` + `as_int16` + `as_uint32_hi_first` / `as_float32_hi_first` (มิเตอร์ส่วนใหญ่ใช้ float 2 register)
  พร้อม note ให้คูณ scale ตามคู่มืออุปกรณ์ · write: เลข 1 ค่า หรือหลายค่าคั่นด้วย comma (holding) · coil on/off
- **โปรโตคอล** `util/ModbusRtu.h` (host test `modbus_rtu_frames`: vector มาตรฐาน C5 CD / 98 0B / 0E 84, exception, CRC ผิด, จำนวนไม่ตรง, coil bits)
  · รอ 3.5 ตัวอักษรก่อนเฟรม · รอคำตอบ 300 ms, ช่องว่างกลางเฟรม 20 ms · timeout/CRC ถามซ้ำ 1 ครั้ง (write ไม่ส่งซ้ำถ้าอุปกรณ์ตอบแล้ว)

## กล้อง OV02C10 + AI มองเห็น (T133)

**เส้นทางภาพ:** OV02C10 1288×728 RAW10 1-lane → `esp_video` "/dev/video0" (ISP ของ P4 แปลงเป็น RGB565) → **PPA** ตัดกลาง 1280×720 + ย่อครึ่ง
+ HFLIP (ตามตัวอย่างผู้ผลิต) → **JPEG ฮาร์ดแวร์** 640×360 คุณภาพ 60 (~25–45 KB) → `GeminiLiveClient::sendImage()` = `realtimeInput.video` (image/jpeg)
ก่อนส่งผลของ tool → โมเดลเห็นภาพตอนตอบ · buffer เฟรม (~3.7 MB PSRAM) มีเฉพาะตอนถ่าย · ข้าม 6 เฟรมแรกให้ภาพนิ่ง

**ทำไมไม่ใช้ `esp_video_init` ตรงๆ:** SDK ของ Arduino ใช้ `esp_cam_sensor` 2.4.0 แบบ **static detect array** (รายชื่อเซนเซอร์ฝังตอน build SDK
ไม่มี OV02C10) → `Camera::begin()` ทำเอง: `esp_video_init_with_flags(ISP)` → SCCB บน `i2cBusHandle(0)` (บัสเดียวกับ Wire, 100 kHz ต่ออุปกรณ์) →
`ov02c10_detect()` (ไดรเวอร์ใน `firmware-p4/lib/ov02c10/`, Apache-2.0) → `esp_video_create_csi_video_device()` (API ภายในของ esp_video 2.4.1 —
ประกาศ struct เองตาม `private_include/esp_video_device_internal.h`, `dont_init_ldo = true` เพราะจอ DSI เปิด LDO ch3 2.5 V แล้ว)

**ปรับแสง/สีอัตโนมัติ (IPA):** SDK มีค่าปรับจูนเฉพาะเซนเซอร์ที่ build ไว้ (OV5647, SC2336 ...) **ไม่มี OV02C10** → ตอนนี้ ISP ใช้ค่าเริ่มต้น
(ภาพอาจมืด/ติดเขียว) · ทางแก้ที่พร้อมแล้วในโค้ด: ฟังก์ชัน weak `pab_ov02c10_ipa_config()` — ถ้ามีไฟล์ที่สร้างจาก JSON ของผู้ผลิต
(`ov02c10_default_p4_eco4.json` สำหรับ `esp32p4`, `eco5` สำหรับ `esp32p4-r3`) ด้วยสคริปต์ `tools/config/esp_ipa_config.py` ของ `esp_ipa` 2.3.0
(Espressif) แล้ว `esp_video_isp_pipeline_init()` จะเปิด AE/AWB/CCM ให้เอง · ⏳ ยังไม่ได้สร้าง (การรันสคริปต์ที่ดาวน์โหลดมาต้องได้รับอนุญาตจากผู้ใช้)

**ใช้งาน:** AI — tool `camera` ("เห็นอะไรบ้าง", "ช่วยอ่านป้ายนี้", "นี่คืออะไร") · console `camera` (ถ่ายทดสอบ บอกขนาด/เวลา) · `camera save`
→ `agent/camera.jpg` บน SD (ดูด้วย SD Explorer ของ Studio) · log ตอนบูต `[Camera] OV02C10 1288x728 -> JPEG 640x360, auto exposure ...`

**ทดสอบบนบอร์ด (ยังไม่ได้ทำ):** `[Camera]` ตอนบูต (เจอ 0x36 / PID 0x5602) → `camera save` → ดูภาพ → ถาม AI "เห็นอะไร" · flash 83.3 % (esp32p4) / 85.3 % (r3)

## T153 — คำปลุก + ไมค์: AI ไม่ "พูดเอง" กับเสียงรอบข้าง (ผู้ใช้ 2026-11-01)

- **พร้อมแล้วยังไม่พูด:** เปิดช่วงฟังต่อ (`AGENT_FOLLOWUP_MS` 6 วิ เริ่มง่าย) + นับเวลาว่างของวิทยุ (6 วิ) จากตอนพร้อม — เหตุที่ T124 ต้องขานรับ
  (กฎวิทยุปิด session 2–3 วิหลังพร้อม) แก้ด้วยการเริ่มนับใหม่ · จอขึ้น "ฟังอยู่ พูดได้เลย"
- **"Hi ESP พักหน้าจอ" รวดเดียว:** ระหว่างเสียงตื่นไมค์อยู่ในโหมดพูดแทรก (เก็บเสียงหลังตัดเสียงสะท้อน) — เสียงที่ดังกว่า 2× เกณฑ์ห้องยังนับเป็นคำพูด
  ไม่งั้นเหลือแค่ 0.6 วิท้ายของคำสั่ง
- **เสียงระหว่างเชื่อมต่อหลังคำปลุกต้องเป็นคำพูด:** ใช้กติกาเดียวกับ T153 (≥ 0.24 วิ, ดัง ≥ 0.012) — ทดสอบครั้งแรกเสียงห้อง 0.2 วิถูกส่ง,
  Gemini ถอดเป็น "Ignacio" แล้วตอบ "คะว่าอย่างไรบ้างคะ" · ไม่ถึง = log `[Mic] หลังคำปลุก: เสียงระหว่างเชื่อมต่อ ... ไม่ใช่คำพูด - ไม่ได้ส่ง`
- log ตอนพร้อม: `[Chat] woken by the wake word, nothing said yet - listening (chime left after echo removal X, voice threshold Y)`
  — เสียงตื่นเหลือหลัง AEC 0.006 (บางครั้ง 0.06–0.10 ปนหางเสียง TTS 3 ช่วง = ตัดทิ้งด้วยกติกาด้านบน)
- **ผล (บอร์ดจริง, TTS จากลำโพง PC):** คำปลุก + เงียบ 2/2 = เสียงตื่น AI ไม่พูด (กับวิทยุ: กลับไปเล่นวิทยุใน 6 วิ) · คำปลุก + คำสั่งรวดเดียว 4/4 ได้ครบ
  ("ช่วยบอกเวลาตอนนี้หน่อย", "พรุ่งนี้อากาศเป็นยังไง") · คำปลุก, รอ 6 วิ, แล้วสั่ง 2/2 ส่งและตอบ
- ⚠️ ไม่มีการขานรับใน turn แรกแล้ว — turn แรกของ session คือคำสั่งของผู้ใช้เลย (เสียง/เพศยังล็อกด้วย prompt)

## T168 — แก้ดึงข้อมูล ThaiWater ทั้งประเทศแล้วบอร์ดค้างถาวร + ยกเลิก web tool ทันทีเมื่อพูดแทรก (ผู้ใช้ 2026-11-02)

ผู้ใช้ถาม *"ปริมาณน้ำฝนสะสมสูงสุดจังหวัดไหน"* (`water {"action":"rain"}` ดึง `public/rain_24h` ทั้งประเทศ ~630 KB gzip → 4.85 MB JSON ผ่าน hotspot มือถือ `HONOR X9d`) แล้วบอร์ดค้างถาวร ขึ้น `[Web] job stuck? stage "water: parse stations" for 45 s ... 150 s` จนจอ/ทัชไม่ตอบสนอง (โค้ดชุดเดียวกันบนทั้ง `firmware-p4/` และ `src/` ของ S3 — แก้พร้อมกันทั้งสองบอร์ด):

1. **ต้นเหตุหลักที่ทำให้บอร์ดค้างถาวร (`GzipHttpStream::fill` + ESP32 ROM `tinfl`):**
   - ในรอบลองใหม่ (Attempt 1 หลังรอบแรกค้างที่ 88 KB `stalled - trying again`) เน็ต hotspot สะดุดเกิน 6 วิกลางบล็อก Huffman (`more == false`, `inSize == 0`)
   - โค้ดเดิมส่งแฟล็ก `more ? TINFL_FLAG_HAS_MORE_INPUT : 0` ให้ `tinfl_decompress` ใน ROM ของ ESP32 — ตามพฤติกรรมของ `miniz` (`TINFL_GET_BYTE`) เมื่อไม่มีแฟล็ก `TINFL_FLAG_HAS_MORE_INPUT` ตัวคลายข้อมูลจะ**ไม่คืนค่า `NEEDS_MORE_INPUT` แต่สังเคราะห์ไบต์ `0x00` ขึ้นมาป้อนตัวเองไม่จำกัด**
   - ในตาราง Huffman ที่รหัส `000...` แทนตัวอักษร/ตัวเลข (ไม่ใช่รหัสจบบล็อก EOB 256) `tinfl` จะพ่นอักขระปลอมเต็มหน้าต่าง 32 KB คืน `HAS_MORE_OUTPUT` ตลอดกาล ส่วน `ArduinoJson` ก็อ่านข้ามสตริง/ตัวเลขปลอมวนไม่รู้จบ โดยที่ `_eof == true` ทำให้ไม่เข้า `delay(2)` ในเน็ตอีกเลย
   - เนื่องจาก task `webTools` รันบน **Core 1 ที่ priority 4** จึงแย่ง CPU 100 % ของ Core 1 บล็อก `ui` (หน้าจอ + ทัช, priority 3), `wakeword` (priority 3) และ `loopTask` (serial console, priority 1) ค้างสนิท ขณะที่ `agent` (priority 5) ยังพิมพ์ `job stuck?` ออกมาได้ทุก 15 วิ
   - **การแก้ไข:** แยก `util/GzipInflate.h` ส่ง `TINFL_FLAG_HAS_MORE_INPUT` ให้ `tinfl_decompress` **เสมอ** (เมื่อข้อมูลหมดจึงคืน `TINFL_STATUS_NEEDS_MORE_INPUT` แล้วออกจากลูปทันทีพร้อมตั้ง `_truncated = true`) + เช็ค zero-progress / negative status + เช็ค `_deadline` และสัญญาณยกเลิกงานใน `rawByte()` / `bodyRead()` + เรียก `delay(1)` ทุก 15 ms ที่ทำงานต่อเนื่อง (`yieldIfBusy()`) เพื่อให้จอ 30 fps และทัชลื่นเสมอแม้กำลังแตกไฟล์หลายเมกะไบต์

2. **บั๊กข้อมูลแหว่งเงียบใน `WaterTools.cpp` และส่วนหัว gzip:**
   - เดิม `runRank()` วนอ่านสถานีด้วย `do { ... } while (s->findUntil(",", "]"));` ซึ่ง `Stream::findUntil` คืน `false` ทั้งเมื่อเจอ `"]"` จบอาเรย์ **และเมื่อสตรีมตัดจบ (EOF/stall)** — หากเน็ตหลุดหลัง `}` พอดี โค้ดเดิมจะถือว่าอ่านสำเร็จและแคชอันดับจังหวัดที่โหลดมาแค่ครึ่งประเทศไว้ 10 นาที · และ `skipGzipHeader()` เดิมไม่เช็ค EOF (`< 0`)
   - **การแก้ไข:** เพิ่ม `thaiwater::parseJsonArrayItems()` บังคับตรวจตัวคั่น `,` หรือ `]` จริงหลังทุกสถานี รองรับ `"data":[]` และรีเซ็ตวันที่เมื่อเริ่มรอบลองใหม่ + เช็ค EOF ทุกไบต์ใน `gzip::skipHeader()`

3. **บั๊กต่อเนื่องอีก 3 จุดที่ปรากฏใน log เดียวกันของผู้ใช้:**

   - **เตือนหลอก `⚠ ส่งเสียงพูดแล้วแต่ AI ไม่ได้ยิน/ไม่ตอบใน 8 วิ` ขณะกำลังโหลด tool (`09:23:43`, `09:24:30`):** เกิดจาก Server VAD เรียก `onToolCall` ก่อนที่ Local VAD จะจบช่วงหางเสียง (`endUtterance` ตั้ง `_replyWatchAt` ทับ) → แก้ `AgentMic.cpp` ไม่ให้ตั้ง/ยิงเตือนไม่มีคำตอบเมื่อ `_webPending > 0`

### app partition เต็มกว่าที่ pio บอก — image มี `.eh_frame` 259 KB

- **อาการ:** build ผ่าน pio รายงาน `Flash 97.0 %` (6,103,194 / 6,291,456) แฟลชแล้ว **บอร์ดบูตไม่ขึ้น**:
  `6363312 doesn't fit in partition length 6291456` → `No bootable app partitions`
- **สาเหตุ:** ตัวเลข Flash % ของ pio นับ `.flash.text` + `.flash.rodata` + data แต่ **ไม่นับ `.eh_frame`** (ตาราง unwind ของ C++ exception —
  Arduino-ESP32 สำหรับ P4 คอมไพล์ด้วย `-fexceptions`, RISC-V เก็บตารางนี้ในแฟลช) ซึ่งอยู่ใน `firmware.bin` จริง 258,700 B ·
  ก่อนงานนี้ image จึงเหลือที่จริงแค่ **~48 KB** (ไม่ใช่ ~300 KB ตามที่ pio บอก) และ tool ใหม่กิน ~120 KB
- **แก้:** `firmware-p4/platformio.ini` เพิ่ม `build_src_flags = -fno-exceptions -fno-unwind-tables -fno-asynchronous-unwind-tables`
  (เฉพาะ `src/` ของเรา — โค้ดเราไม่มี `try` / `catch` / `throw` เลย; exception จาก libstdc++ เช่น out of memory จบที่ `abort()` เหมือนเดิม ·
  SDK และไลบรารียังมีตารางของตัวเอง) → `.eh_frame` 258,700 → 118,672 B, `.flash.text` −33 KB → **`firmware.bin` 6,167,280 B (98.0 %, เหลือ 124 KB)**
  มากกว่าก่อนเริ่มงาน
- **วิธีดูขนาดจริง:** `ls -l firmware-p4/.pio/build/esp32p4-r3/firmware.bin` เทียบ 6,291,456 (อย่าเชื่อ Flash % ของ pio บน P4) ·
  `riscv32-esp-elf-size -A firmware.elf | grep eh_frame`
- **ยังเหลือ:** ที่ว่าง 124 KB ถือว่าน้อย — tool ใหญ่ตัวถัดไปต้องลดอย่างอื่นก่อน (เช่น build ไลบรารีแบบไม่มี unwind table ด้วย หรือทบทวน partition)
